# 再平衡与调仓节奏

再平衡是把组合权重从"漂移后的实际值"拉回"目标值"的过程。它看起来只是维护动作，实际上既是**风险控制**（防止风险贡献漂移），也可能是**收益来源**（再平衡溢价），同时又是**成本中心**。搞清楚这三者的平衡是本节的主题。

## 一、再平衡溢价从哪来

考虑两只不相关、各自年化波动 20%、长期期望收益相同的资产，各持 50%。若价格随机游走且存在波动，定期再平衡到 50/50 的组合，其几何收益会**高于**买入持有。原因是：

设两资产在 $t$ 期收益分别为 $r_1,r_2$，则买入持有组合收益为 $\frac{1}{2}r_1+\frac{1}{2}r_2$；再平衡组合在每期末卖出涨的、买入跌的，其收益为

$$r_{rb} \approx \frac{r_1+r_2}{2} + \underbrace{\frac{(r_1-r_2)^2}{4}}_{\text{波动率捕获项}} \quad (\text{忽略成本})$$

这一正项就是**再平衡溢价（rebalancing premium / volatility harvesting）**，由 Fernholz 的**随机组合理论**给出严格刻画：再平衡组合相对买入持有的超额增长率为

$$\gamma^\*(t) = \frac{1}{2}\sum_{i=1}^{N} w_i(t)\,\tau_{ii}^\*(t)$$

其中 $\tau_{ii}^\*$ 是资产 $i$ 的**超额收益率过程的方差**。注意这里的关键字是"方差"而非"协方差"——溢价来自**资产之间的相对波动（离差）**，而不是资产自身的绝对收益。

成立条件与失效情形：

| 条件 | 是否有溢价 |
| --- | --- |
| 资产间波动大、相关性低 | 溢价显著 |
| 资产走势高度同步（$\rho\to1$） | 溢价趋近 0 |
| 存在趋势/动量（收益正自相关） | 溢价可能变负（"再平衡惩罚"） |
| 交易成本高于溢价 | 净收益为负 |
| 单一资产长期跑赢（如优质成长股） | 再平衡会持续减仓赢家，损害收益 |

因此：**再平衡溢价是"卖掉赢家买输家"的均值回复赌注**。它和 [止损](08-05-止损与回撤控制.md) 的逻辑正好相反——趋势策略靠"让赢家奔跑"，再平衡靠"削减赢家"。同一个组合里同时用这两套逻辑会互相抵消，必须分清主次。

## 二、定期 vs 阈值（缓冲带）

### 定期再平衡

按固定日历（日/周/月/季）执行。优点：规则简单、可预测、便于合规与容量管理。缺点：无论漂移多小都交易，产生大量无意义的噪声交易。

### 阈值（百分比带宽）再平衡

定义容忍带：当 $|w_i - w_i^{target}| > \delta$ 或相对偏离 $|w_i/w_i^{target}-1|>\delta_{rel}$ 时才交易。$\delta$ 的典型值为 20%~25% 相对带宽。

优点：只在真正偏离时交易，换手显著下降；且天然"让赢家跑一段"。缺点：需要每日监控、成交时机不规则、在单边行情中可能很久不触发。

### 混合式（推荐）

**定期 + 缓冲带**：每月检查一次，但只调整超出容忍带的头寸。这是实务中最常见的折中，也叫 buffer rebalancing。

| 方案 | 换手 | 跟踪误差 | 成本 | 适用 |
| --- | --- | --- | --- | --- |
| 每日 | 最高 | 最低 | 最高 | 低成本、大容量 |
| 月度 | 中 | 低 | 中 | 通用默认 |
| 季度 | 低 | 中 | 低 | 高成本市场 |
| 20% 缓冲带 | 最低 | 中高 | 最低 | 成本敏感 |

## 三、成本权衡：最优频率怎么定

设再平衡的年度毛收益（溢价）为 $B(f)$，随频率 $f$ 增加而增加但边际递减（大致 $B\propto\sqrt{f}$ 或对数增长）；年度成本 $C(f)\approx c\cdot\text{Turnover}(f)$，随频率近似线性增长。净收益 $N(f)=B(f)-C(f)$，最优 $f$ 满足 $B'(f)=C'(f)$。

三条实用结论：

1. **成本主导**。A股单边印花税 0.05%（2015 年后为 0.05% 单边，此处按 `stamp_tax=0.0005` 建模）+ 佣金万三 + 滑点 5bps，一次完整换手的成本约 15~25bps。若年化再平衡溢价只有 50~100bps，那么**季度再平衡通常优于月度**。
2. **容量约束**。资金量增大后冲击成本上升（见 [冲击成本模型](../09-执行与成本/09-03-冲击成本模型.md)），最优频率自动下降。
3. **信号半衰期决定上限**。再平衡再频繁也不会比信号更新更快更有价值。用 `FactorLab.ic_decay` 观察因子的 IC 衰减，若 IC 半衰期是 20 个交易日，那么比月度更快的调仓没有信息增量。

## 四、代码示例

```python
import numpy as np
from qd.data.synthetic import generate_demo_market
from qd.optimize import grid_search
from qd.strategy.builtin import factor_long_only
from qd.backtest import Backtest, BacktestConfig
from qd.metrics.perf import sharpe, annual_return

md = generate_demo_market(n_symbols=60, start="2018-01-01", end="2024-12-31", seed=7)

def run(rebalance, slippage_bps):
    strat = factor_long_only(factors=["mom_12_1", "vol_20d"], top_k=20,
                             rebalance=rebalance)
    cfg = BacktestConfig(initial_cash=1_000_000, commission_rate=0.0003,
                         slippage_bps=slippage_bps, stamp_tax=0.0005,
                         allow_short=False, t_plus_1=True)
    res = Backtest(md, strat, cfg).run()
    r = res.equity.pct_change().dropna().values
    return dict(rebalance=rebalance, slippage_bps=slippage_bps,
                sharpe=sharpe(r), annual=annual_return(r),
                turnover=float(np.abs(np.diff(
                    res.equity.pct_change().fillna(0).values)).sum()))

grid = grid_search(run, {"rebalance": ["1M", "3M", "6M"],
                         "slippage_bps": [5, 20, 50]})
for row in grid:
    print("频率=%-3s 滑点=%2dbps 夏普=%.2f 年化=%6.2f%%"
          % (row["rebalance"], row["slippage_bps"], row["sharpe"], row["annual"]*100))
```

缓冲带再平衡的伪代码（可直接嵌入自定义策略）：

```python
def buffer_rebalance(target, current, delta=0.20):
    """只在相对偏离超过 delta 时才交易，其余保持不变。"""
    w = current.copy()
    mask = np.abs(current / np.maximum(target, 1e-9) - 1.0) > delta
    w[mask] = target[mask]
    w = np.clip(w, 0.0, None)
    return w / w.sum()          # 归一化回预算约束
```

## 常见坑

- **用收盘价回测却在实盘用开盘价**：再平衡的成交价假设必须一致，否则收益差出一个数量级。
- **忽略分红、拆股、配股等公司行为**：会造成虚假的权重漂移，触发无意义交易。
- **再平衡日与信号日不一致**：信号算完当天就交易，容易用到当日收盘价（前视）。正确做法是信号用 $t$ 日收盘、交易用 $t+1$ 日。
- **只看收益不看换手**：[换手率控制](../09-执行与成本/09-04-换手率控制.md) 与再平衡是一体两面，必须一起评估。
- **把所有标的都拉回目标**：小额漂移交易的手续费占比高，缓冲带能省下大量成本。
- **忘记涨跌停**：再平衡日若标的一字板，订单无法成交，需要顺延逻辑（见 [订单类型](../09-执行与成本/09-01-订单类型.md)）。
