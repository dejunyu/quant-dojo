# 样本内外与滚动前推

## 学完这一篇，你能做到

- 说清"样本外只能用一次"是什么意思，以及为什么
- 正确切分训练/验证/测试集，知道 embargo 在挡什么
- 用 `walk_forward` 做滚动前推，并读懂它输出的"跳变"
- 明白为什么**随机 K 折在时序数据上是非法的**

## 本篇要点

- 样本外的价值来自"**你没见过**"；看第二次它就不算样本外了
- **随机切分在时间序列上必然泄漏**（未来标签渗进训练集）
- 净化 K 折 = purge（删重叠）+ embargo（留缓冲）
- 滚动前推是"**多次模拟真实研究过程**"，比一次性切分更诚实

---

## 一、从统计学半个世纪前的老办法说起

1974 年，统计学家 **M. Stone** 在《皇家统计学会会刊 B 辑》发表《交叉验证选择与统计预测评估》（*JRSS-B* 36(2): 111–133）。

他讨论的问题，在今天听起来极其熟悉：**你有一堆数据，想评估一个预测方法好不好，该怎么做？**

Stone 的答案构成了后来所有"交叉验证"的骨架：**留出一部分数据不参与建模，用它来检验**。这个想法后来被机器学习发扬光大，成了 `train_test_split`、`cross_val_score` 这些每个人都在用的函数。（[Wikipedia: Cross-validation](https://en.wikipedia.org/wiki/Cross-validation_(statistics))）

> **这件事值得强调的一点是：样本外检验不是量化圈发明的土办法，是统计学半个世纪的正统。**
> 你在 06-05 里为"试了 144 次"焦虑，其实 1974 年就有人给出了对策的雏形：
> **别用你拟合过的数据来评价你自己。**

但金融数据有个特殊之处，让这个"老办法"直接照搬会出事——**时间是不可逆的**。

---

## 二、为什么随机切分无效（讲透）

机器学习里最常见的做法是**随机打乱**后按 8:2 切。在图像分类里没问题，在金融数据里**必然泄漏**。

原因有两个：

1. **标签有窗口**：你预测"未来 20 日收益"，那么第 100 天的标签里，包含了第 101~120 天的信息。如果第 105 天被分进训练集，**训练集就已经知道了测试集的未来**。
2. **样本有时间相关**：相邻交易日的特征高度相似。随机切分会让"几乎同一天"的两条数据分别落进训练集和测试集——**等于开卷考试**。

> **所以金融时序的切分规则只有一条：**
> **训练集必须整段早于测试集，中间还要留缓冲。**

补个常识：**交叉验证（cross-validation）** 在统计学里是"反复留一部分作验证"的通用方法；但在金融里，它必须加两个补丁：**purging（净化）** 与 **embargo（禁飞区）**，否则就退化成随机切分。

---

## 三、三段式切分（最朴素也最实用）

```
[———— 训练 ————][— 验证 —][—— 测试 ——]
      用来选参数      用来挑方案     只用一次
```

| 段 | 用途 | 可以看几次 |
| --- | --- | --- |
| **训练（train）** | 估参数、找规律 | 无数次 |
| **验证（valid）** | 比较不同方案、调超参 | 有限次（会疲劳） |
| **测试（test）** | 最终"上考场" | **一次** |

> ⚠️ **"样本外只能用一次"是这一篇最重要的一句话。**
> 你每看一次测试集、每根据它改一次代码，它的"样本外"身份就损耗一点——
> 因为你的决策已经悄悄拟合了它。
>
> 这就是 06-05 说的：**试的次数要记账**。测试集被你看过 5 次，它就不再是"没见过"的数据了。

## 四、净化 K 折与滚动前推

### 净化 K 折（purged k-fold）

普通 K 折：把数据分 K 份，轮流拿一份当测试。
**金融版**要多做两件事：

| 动作 | 做什么 | 挡什么 |
| --- | --- | --- |
| **purge（净化）** | 删掉与测试集**时间重叠**的训练样本 | 标签窗口重叠泄漏 |
| **embargo（禁飞区）** | 在训练与测试之间**留一段空白** | 序列自相关泄漏 |

> Marcos López de Prado 在《Advances in Financial Machine Learning》（Wiley，2018）第 7 章系统化了这套做法。
> 记住它的核心：**不是把数据切干净，而是把"时间上的邻居"也切掉。**

### 缓冲期该留多长（一个公式讲透）

**embargo 不是随便留几天。** 它至少要和"标签窗口 + 序列相关长度"一样宽：

$$\text{embargo} \ge h + \rho$$

| 符号 | 白话 |
| --- | --- |
| $h$ | 你的标签窗口（预测未来多少期） |
| $\rho$ | 收益序列的显著自相关长度 |
| 求和 | 两者相加，才是安全的空白 |

举例：你预测"未来 20 日收益"（$h=20$），而收益序列显著自相关约 5 天（$\rho \approx 5$），那么 **embargo 至少要 25 天**。

> **为什么是相加而不是取大？** 因为两种泄漏是**叠加**的：
> 标签窗口让"第 100 天的样本"含到第 120 天；
> 自相关让"第 121 天"又和第 120 天高度相关。
> **只堵一个，另一个照样漏。**

### 滚动前推（walk-forward）

这是最贴近真实研究过程的验证方式：

```
第 1 段：用 2018-2020 选参数 → 在 2021 上半年验证
第 2 段：用 2018-2021 选参数 → 在 2021 下半年验证
第 3 段：用 2018-2022 选参数 → 在 2022 上半年验证
……一段段往前推
```

> **它的诚实之处在于：它承认"参数会过期"。**
> 一次性切分是"拿 2015 年调好的参数，一路用到 2025 年"；
> 滚动前推是"**每年重新考一次试**"。
> 后者显然更接近你真实会做的事。

## 五、用平台跑一遍

按 [00-开始之前](../01-入门/00-开始之前.md) 装好环境，把下面这段存成文件跑一次：

```python
import warnings
warnings.filterwarnings("ignore")
from qd.data.synthetic import generate_demo_market
from qd.backtest import Backtest, BacktestConfig
from qd.strategy.builtin import sma_cross
from qd.optimize import walk_forward, purged_kfold, grid_search
from qd.metrics.perf import sharpe

md = generate_demo_market(n_symbols=50, start="2018-01-01", end="2024-12-31", seed=7)
cfg = BacktestConfig(initial_cash=1_000_000)
grid = {"fast": [5, 10, 20, 30], "slow": [60, 120, 180]}

# 1) 三段切分
train = md.slice("2018-01-01", "2021-12-31")
valid = md.slice("2022-01-01", "2022-12-31")
test = md.slice("2023-01-01", "2024-12-31")

best = grid_search(train, sma_cross, grid, metric="sharpe", verbose=False)
print("训练期最优:", best["params"], "Sharpe:", round(best["score"], 4))
for name, seg in [("验证", valid), ("测试", test)]:
    res = Backtest(seg, sma_cross(**best["params"]), cfg).run()
    print(f"{name}期 Sharpe:", round(sharpe(res.equity, rf=0.02), 4))

# 2) 滚动前推：多次模拟"当时的研究流程"
wf = walk_forward(md, sma_cross, grid, n_splits=5,
                  train_window=756, test_window=126, metric="sharpe")
print("各段样本外 Sharpe:", [round(s, 3) if s == s else None for s in wf["scores"]])

# 3) 净化 K 折
folds = purged_kfold(md, n_splits=5, embargo=20)
print("折数:", len(folds))
```

我实跑的结果：

```
训练期最优: {'fast': 20, 'slow': 180} Sharpe: -0.0347
验证期 Sharpe: -0.2233
测试期 Sharpe: 0.7803
各段样本外 Sharpe: [-1.832, None, None, 0.297, None, -0.522, None, None, -3.263]
折数: 5
```

**这三行数字，是一堂完整的课：**

| 段 | Sharpe | 发生了什么 |
| --- | --- | --- |
| 训练 | **-0.0347** | 9 组参数里挑出来的"最优"，本来就是负的 |
| 验证 | **-0.2233** | 更差 |
| 测试 | **0.7803** | 突然很好 |

> **如果我只看测试集那 0.78，我会以为找到了一个不错的策略。**
> 但把它和训练（-0.03）、验证（-0.22）放在一起，
> 真相就露出来了：**这不是"策略有效"，这是"某一段行情恰好适合这组参数"。**

再看滚动前推那一行：**-1.832、0.297、-0.522、-3.263**（部分是 `None`，表示该段无有效成交或数据不足）。

> **段与段之间跳到 -3.26，说明参数在不同年份选出来的东西完全不一样**——
> 这正是 06-05 讲的"过拟合"在时间维度上的样子。
> **一个真有效的策略，各段样本外不会跳成这样。**

> 补一个常识：`None` 对应引擎返回的 `nan`。**在样本外检验里，"某段算不出来"本身就是信息**——
> 它通常意味着那段时间的成交条件极端（如几乎无有效成交），而这类时段恰恰是你最该关注的。

## 六、结果怎么解读

| 观察 | 判断 | 该做什么 |
| --- | --- | --- |
| 样本内远好于样本外 | 过拟合 | 减参数、加约束、提高机制说服力 |
| **各段样本外方差极大** | 策略不稳定，吃行情状态 | **别用了，或换低频** |
| 样本外系统性低于样本内但仍为正 | **正常** | 关注稳定性，不是差距本身 |
| 滚动前推各段参数频繁跳变 | **参数不可识别** | 改用固定参数或等权方案 |
| 样本外收益集中在某一两段 | 偶然性大 | 延长样本 |

> **一句话经验：接受"样本外比样本内差"，它是常态。**
> 真正该警惕的只有两件事：**差距过大**（如样本内 2.5、样本外 0.2），
> 以及**样本外自己跳来跳去**（本篇那行 -1.83 到 -3.26）。

## 七、把这一篇串起来

回到 Stone 1974 年那篇论文。

他给的是一个极其朴素的建议：**别用你拟合过的数据，来评价你自己。** 半个世纪过去，这句话在金融里不但没失效，反而更需要强调——因为金融数据既不可重复，又充满时间相关。

> 06-05 说"过拟合是心理倾向"，这一篇给的是**工程对策**：
> 把"我什么时候能看到什么"制度化。
> **训练期随便看、验证期有限看、测试期只看一次**——这不是自虐，是让你在真金白银之前，先诚实地被考一次。

> 一句话收尾：
> **样本外的价值，不来自"数据新"，来自"你没见过"。**
> 一旦你根据它改过代码，它就变成了训练集的一部分——
> **而你还以为自己在做样本外检验。**
