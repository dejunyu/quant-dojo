# 主流回测框架对比

选框架不是为了用最流行的，而是为了让你的**策略类型**和**验证严谨度**得到最好的支持。本篇对比六个常见选择，并给出决策路径。

## 一、框架总览

| 框架 | 执行模型 | 语言 | 主要优势 | 主要短板 | 适合谁 |
| --- | --- | --- | --- | --- | --- |
| backtrader | 事件驱动 | Python | 概念清晰、社区大、支持多数据源与券商对接 | 性能一般，大数据集慢 | 学习事件驱动、单品种时序策略 |
| zipline | 事件驱动 | Python | 曾经的行业标准，内置 Pipeline 因子框架 | 维护活跃度下降，安装依赖较重 | 研究美股、复现经典研究 |
| vectorbt | 向量化 | Python | 极快，参数扫描能力强，与 pandas/numpy 无缝 | 难表达路径依赖与精细撮合 | 因子研究、大规模参数扫描 |
| bt | 向量化 | Python | 组合构建与权重树抽象优雅，便于资产配置 | 生态较小 | 资产配置、组合回测 |
| qlib | 全流程 | Python | 微软开源，覆盖数据→模型→回测，内置大量 AI 模型 | 体系庞大，学习曲线陡 | AI 驱动的多因子研究 |
| 自研 | 自定义 | Python/C++ | 完全掌控撮合、成本、容量模型 | 开发维护成本高，易有隐藏 bug | 有明确差异化需求的专业团队 |

## 二、按执行模型理解差异

判断一个框架属于哪一类的简单方法：看它的核心循环是否逐 bar 推进。事件驱动框架每期只处理一期数据，状态量（仓位、现金）以标量形式维护；向量化框架一次性处理整个面板，组合收益就是信号矩阵与收益矩阵的逐元素乘积再求和：

$$ r_{p,t} = \sum_i w_{i,t}\, r_{i,t+1} $$

[回测的两种实现](../06-回测/06-01-回测的两种实现.md)已经说明了两种模型的原理，这里只强调选型含义：

- **事件驱动框架（backtrader、zipline）** 的核心抽象是 `next()` 或 `handle_data()`，每个 bar 调用一次，可以访问 `self.position`、`self.broker`。你能自然地表达"跌破止损就卖"、"资金不足就减少下单"，代价是速度。
- **向量化框架（vectorbt、bt）** 的核心是信号矩阵，一次运算完成全部回测。你能在一分钟内扫描几千组参数，代价是止盈止损、部分成交这类逻辑要么无法表达，要么需要用特殊技巧近似。

平台的 `Backtest` 属于**事件驱动**，`FactorLab` 的分层回测与 IC 检验属于**向量化**。两者配合正好覆盖"快速筛选 + 严格验证"的完整流程。

## 三、按策略类型选择

| 策略类型 | 推荐框架 | 理由 |
| --- | --- | --- |
| 横截面多因子选股 | qlib / vectorbt / 平台 FactorLab | 需要大量横截面运算与因子检验 |
| CTA 趋势跟踪 | backtrader / 自研 | 需要止损、加仓、保证金等路径逻辑 |
| 配对交易 | backtrader / 自研 | 需要成对下单与仓位联动 |
| 资产配置轮动 | bt | 权重树抽象天然适合 |
| 高频 / 分钟级 | 自研（事件驱动 + C++ 内核） | 通用框架性能与撮合精度不足 |
| 参数扫描研究 | vectorbt | 速度是关键 |

## 四、选型的四个决定性因素

1. **策略频率与规模**：日频几百只股票，任何框架都够用；分钟级全市场，只有向量化或自研能跑。
2. **是否需要精细撮合**：若你的 alpha 很薄、成本敏感（[撮合滑点与成交假设](../06-回测/06-02-撮合滑点与成交假设.md)），通用框架的成本模型往往不够，需要自研或深度定制。
3. **数据生态**：美股数据 zipline 生态成熟；A 股通常需自建数据层或选用支持国内数据源的方案。数据接入的工作量通常远超回测本身。
4. **团队维护能力**：qlib、backtrader 这类大型框架的学习与维护成本不低；若团队只有 1~2 人，一个简洁的自研事件驱动循环可能更可控。

## 五、自研的合理边界

自研常被批评为重复造轮子，但有三条合理理由：

- **需要完全掌控撮合与成本模型**：通用框架的成本模型是黑箱或过于简化，而专业团队的核心竞争力恰在成本估计；
- **需要与实盘执行系统共享代码**：回测与实盘用同一套撮合逻辑，可以消除"回测一套、实盘另一套"的系统性偏差；
- **性能或合规要求**：低延迟、内网部署、审计留痕等要求无法被通用框架满足。

但自研的**最低要求**是：必须有完整的单元测试、必须与至少一个开源框架在相同策略上做过结果对账。缺少这两条的自研框架，其可信度低于任何成熟框架。

## 六、平台上的位置

本项目的 `qd` 库提供了两条路径，可以同时使用：

```python
from qd.research.lab import FactorLab          # 向量化：因子检验
from qd.backtest import Backtest, BacktestConfig  # 事件驱动：严格回测
from qd.strategy.builtin import factor_long_only
from qd.data.synthetic import generate_demo_market

md = generate_demo_market(n_symbols=50, start="2018-01-01", end="2024-12-31", seed=7)

# 向量化：快速看因子有没有信息
lab = FactorLab(md)
print("IC:", lab.ic("mom_12_1", horizon=20))
print("5分组:", lab.quantile_backtest("mom_12_1", n_quantiles=5))

# 事件驱动：加上成本与约束后看还能不能赚钱
res = Backtest(
    md,
    factor_long_only(factors=["mom_12_1", "bp"], top_k=10, rebalance=20),
    BacktestConfig(initial_cash=1_000_000, commission=0.0003, slippage=0.0005),
).run()
print(res.summary())
```

先用向量化排除无效想法，再用事件驱动验证幸存者——这是成本最低的研究路径。

## 常见坑

1. **用框架默认成本参数**：多数框架默认为零成本或极低佣金，不显式设置等于假设无摩擦。
2. **误用向量化框架做止损策略**：强行表达路径依赖，得到错误结果而不自知。
3. **忽视框架的成交假设**：不同框架默认在"当日收盘"或"次日开盘"成交，差异巨大。
4. **版本与依赖地狱**：zipline 等框架的依赖锁定严格，环境搭建成本可能超过开发成本。
5. **框架能回测就以为能实盘**：绝大多数框架不含实盘执行、风控、监控模块，那部分需要自己补。
6. **自研不做对账**：没有与成熟框架交叉验证的自研引擎，bug 可能潜伏数年。
