# 前视偏差的十种来源

**前视偏差（look-ahead bias）**指回测中使用了在决策时点尚不可获得的信息。它是回测失真最主要的单一来源，特点是：收益虚高、回撤虚低、且往往在策略越"聪明"时越严重。本篇逐条列出十种来源，并给出各自的检测方法。

## 一、未来函数（shift 方向错误）

**表现**：用第 $t$ 期的收盘价生成信号，却按第 $t$ 期收盘价成交；或用 `shift(-1)` 而非 `shift(1)`。

**检测**：逐行检查所有 `shift`、`rolling`、`pct_change` 的参数符号。标准写法是

$$ w_{i,t} = f(\text{info}_{\le t}),\qquad r_{i,t}^{\text{realized}} = w_{i,t} \cdot r_{i,t+1} $$

**通用测试**：构造一个"只用前 $n$ 天数据"的函数，用全样本算出的第 $t$ 日信号，应当与截断数据算出的完全一致。若不一致，说明信号依赖了未来。

```python
from qd.data.synthetic import generate_demo_market

md = generate_demo_market(n_symbols=50, start="2018-01-01", end="2024-12-31", seed=7)
full = md.slice("2018-01-01", "2024-12-31")
cut = md.slice("2018-01-01", "2021-12-31")   # 截断到 2021 年底

sig_full = full.close().rolling(20).mean()
sig_cut = cut.close().rolling(20).mean()
# 2021-12-31 及之前的信号必须完全一致
assert sig_full.loc[:sig_cut.index[-1]].equals(sig_cut)
```

## 二、财报按报告期而非披露日对齐

**表现**：一季报（报告期 3 月 31 日）在 3 月 31 日入库，但多数公司在 4 月中下旬才披露。

**检测**：统计每个财报的 `ann_date` 与 `period_end` 之差的分布，若入库时点等于报告期，必有问题。正确做法是**按披露日映射**：在 `ann_date` 之前该数据不可见。

这一条对基本面因子（[因子构造](../05-因子/05-02-因子构造.md)）影响最大，会让价值、质量因子的 IC 显著虚高。

## 三、复权处理不当

**表现**：用未复权价计算收益率，除权除息日出现假暴跌（如 10 送 10 导致价格腰斩）。

**检测**：检查是否存在单日收益率小于 -10%（A 股有涨跌停限制，个股单日跌幅超过 11% 基本只可能来自除权或数据错误）。应统一使用后复权价或复权因子还原的价格序列。

## 四、停牌处理不当

**表现**：停牌日价格为 NaN 或前值填充，收益率为 0，导致波动率被低估、持仓权重被错误计算。

**检测**：统计每日有成交的股票数量，停牌期间成交量应为 0 而非缺失。正确处理是：停牌期间不可交易，持仓被动延续，复牌后按真实价格计算收益。

## 五、指数成分股的历史成分错误

**表现**：用**当前**的沪深 300 成分股去回测 2015 年的策略，等于提前知道了哪些股票后来被纳入指数。

**检测**：指数成分必须按**历史生效日**逐期映射，且成分调整通常提前公告、在生效日实施。使用"当前成分"回测会得到虚高的超额收益——因为被纳入的股票往往前期表现好。

## 六、参数在全样本上优化

**表现**：用 2018—2024 的全部数据选出最优参数（如均线 23/57），然后声称该策略在这段历史上年化 20%。

**检测**：任何在完整样本上选定的参数、因子、股票池定义，都必须通过[样本内外与滚动前推](../06-回测/06-06-样本内外与滚动前推.md)重新检验。这是最隐蔽也最普遍的一种前视偏差，因为它不涉及数据错误，而涉及**方法论错误**。

## 七、数据修订（restatement）

**表现**：使用最新的数据库快照，其中历史财务数据已被追溯修订（如公司重述 earnings）。

**检测**：对比不同时点下载的同一份历史数据，若存在差异则说明存在修订。理想方案是使用**点-in-time（PIT）数据库**，每条记录同时保存"报告值"与"首次可得时点"。

## 八、幸存者偏差

**表现**：股票池只包含当前仍在交易的股票，退市、被并购的标的被剔除。

**检测**：检查股票池是否逐年变化、是否包含已退市标的。幸存者偏差会系统性剔除最糟糕的样本，使策略的历史回撤看起来远小于真实情况。严格说这属于选择偏差而非前视偏差，但二者常同时出现。

## 九、信号与收益的对齐口径不一致

**表现**：月度调仓策略用月度信号，却用日度收益累乘；或持有期 20 日的因子与 5 日调仓混用。

**检测**：明确写出三件事——**信号生成频率、调仓频率、持有期**——并检查三者是否自洽。三者不一致时，重叠收益会产生自相关，显著性检验失效（[单因子检验IC与ICIR](../05-因子/05-05-单因子检验IC与ICIR.md)）。

## 十、另类数据的时间戳

**表现**：新闻情绪、分析师评级、卫星图像等数据的时间戳采用"事件发生时间"而非"数据可得时间"。

**检测**：检查另类数据是否含有 `publish_time` 与 `event_time` 两个字段，回测必须使用前者。这类数据的泄漏往往非常隐蔽，因为它们的入库时间通常是"批量补录"。

## 十一、交付前的自查清单

| # | 检查项 | 通过标准 |
| --- | --- | --- |
| 1 | 所有 `shift` 方向 | 信号一律 `shift(1)` 后再乘收益 |
| 2 | 财报对齐 | 按 `ann_date` 而非 `period_end` |
| 3 | 价格复权 | 统一后复权，无超阈值单日跳空 |
| 4 | 停牌处理 | 停牌日不可交易，收益 NaN 而非 0 |
| 5 | 指数成分 | 按历史生效日映射 |
| 6 | 参数来源 | 参数只来自训练期，非全样本 |
| 7 | 数据快照 | 使用 PIT 数据或确认无修订 |
| 8 | 股票池 | 含退市股，逐年动态 |
| 9 | 频率自洽 | 信号/调仓/持有期三者一致 |
| 10 | 另类数据 | 用 publish_time |

## 常见坑

1. **以为只有数据才有前视偏差**：参数选择、因子筛选、股票池定义同样会引入，而且更常见。
2. **截断测试只做一次**：每个新因子、每次数据更新后都应重跑。
3. **用 `.fillna(method="ffill")` 填充财报**：会把未披露的财报前值填充到未来，属于隐蔽泄漏。
4. **回测"看起来太好了"却不去怀疑**：年化 40%、Sharpe 3 的日频策略，第一反应应该是找 bug，而不是庆祝。
5. **只检查代码不检查数据**：数据供应商的历史数据本身可能已含修订，代码正确也无济于事。
