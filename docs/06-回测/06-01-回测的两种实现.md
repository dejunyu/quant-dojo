# 回测的两种实现

## 学完这一篇，你能做到

- 说清"向量化"和"事件驱动"两种回测的根本差别
- 知道各自擅长什么、会在什么地方骗你
- 明白为什么**回测引擎和实盘引擎最好是同一个**
- 会用平台跑一次事件驱动回测，看懂 net value / trades / positions

## 本篇要点

- 向量化 = **一整张表一起算**，快，但很难表达"路径依赖"
- 事件驱动 = **一根 K 线一根 K 线地走**，慢，但能模拟真实成交
- 向量化最容易死在"**对齐**"上（`shift(1)` 那一行）
- 最终判断标准：**它能不能描述你实际会下的那些单**

---

## 一、从一句 README 说起

2011 年，**John Fawcett** 与 **Jean Bredeche** 在波士顿创立了 **Quantopian**——一个想让普通人也能写量化策略的平台。它开源出来的回测引擎叫 **Zipline**。

Zipline 的 README 里有一句自我定义，非常值得玩味：

> **"an event-driven system for backtesting"**（一个事件驱动的回测系统）

**为什么值得玩味？** 因为事件驱动写起来慢、代码量大、状态管理复杂。如果目标只是"快点跑出个回测"，向量化明显更划算。Zipline 选事件驱动，是因为它的野心不止回测——它同时要驱动**实盘交易**（README 里写明 "used in production as the backtesting and live-trading engine"）。

（Zipline 首个 PyPI 版本 0.5.0 发布于 2012-10-19。Quantopian 在 2020 年 11 月关停，Zipline 由社区项目 `zipline-reloaded` 接手。）

> **这个故事里藏着本篇最重要的一个判断：**
> **回测引擎的形状，应该由"你要怎么交易"决定，而不是由"你想多快跑完"决定。**
>
> 如果你的策略要盘中挂限价单、要处理部分成交、要被涨停挡住——
> 那么"快"救不了你，**只有事件驱动才能描述它**。
>
> 而更狠的一条经验是：**回测引擎和实盘引擎最好是同一套代码。**
> 两套代码 = 两套 bug = 回测与实盘之间那道缝（06-07 会讲这道缝有多贵）。

---

## 二、向量化回测：把整张表一起算

向量化把回测看成一系列矩阵运算。核心数据结构是 `dates × symbols` 的二维表（02-07 讲过的形状）：

- 价格面板 $P_{t,i}$
- 信号面板 $S_{t,i}$（目标权重）
- 收益面板 $r_{t,i}$

组合收益直接由**逐元素相乘**得到：

$$ r_{p,t} = \sum_{i} w_{i,t} \cdot r_{i,t+1} $$

| 符号 | 白话 |
| --- | --- |
| $w_{i,t}$ | t 日给股票 i 的目标权重 |
| $r_{i,t+1}$ | 它**下一期**的收益 |
| $\sum_i$ | 把所有股票加起来 |

**关键是那个 $t+1$**：信号在 t 日生成，收益必须用 t+1 日。写成 pandas 就是 `signal.shift(1) * ret`。

| 优点 | 缺点 |
| --- | --- |
| 极快（百万数据点秒级） | **难以表达路径依赖**（止盈止损、已有持仓状态） |
| 代码短、易审查 | **成交假设隐含粗糙**（默认"收盘价全部成交"） |
| 天然支持横截面运算 | 无法模拟排队、部分成交、撤单 |

> **所以向量化最适合横截面选股类策略**（多因子选股、截面动量），以及因子检验（05-06 的分层回测就是纯向量化思维）。

## 三、事件驱动回测：一根 K 线一根 K 线地走

事件驱动模拟一个真实的交易循环：

```text
for each bar in timeline:
    1. 接收行情（bar）
    2. 策略算目标仓位 → 生成订单
    3. 撮合引擎按成交假设撮合（价格、滑点、成交量限制）
    4. 更新持仓、现金、组合市值
    5. 记录当期状态
```

核心数据结构是一组**可变状态**：现金、持仓字典、订单队列、成交记录。

| 优点 | 缺点 |
| --- | --- |
| 能精确表达成交假设（次日开盘、限价、涨跌停不可成交、部分成交） | **慢**（Python 循环是瓶颈） |
| 天然支持路径依赖（止损、加减仓、保证金） | 代码量大、状态管理复杂、易出 bug |
| 逐笔成交可审查，便于排查 | 并行化困难 |

> **事件驱动是任何"准备上实盘"的策略的必选项。**
> 因为 03-01、03-05、06-02 讲的每一条约束，都要求你知道"这一笔单在什么时候、以什么价、成交了多少"——
> 这正是向量化那张表**结构上表达不了**的东西。

## 四、用平台跑两种实现（对照看）

按 [00-开始之前](../01-入门/00-开始之前.md) 装好环境。

**先看向量化（短、快、但粗糙）：**

```python
import pandas as pd
from qd.data.synthetic import generate_demo_market
from qd.metrics.perf import perf_report

md = generate_demo_market(n_symbols=50, start="2018-01-01", end="2024-12-31", seed=7)
close = md.close()

# 1) 信号：20 日均线上穿 60 日均线 → 目标权重 1，否则 0
signal = (close.rolling(20).mean() > close.rolling(60).mean()).astype(float)

# 2) 关键对齐：t 日信号，对应 t+1 日收益
ret = close.pct_change()
port_ret = (signal.shift(1) * ret).mean(axis=1)

# 3) 绩效
nav = (1 + port_ret.fillna(0)).cumprod()
print(perf_report(nav, rf=0.02))
```

**再看事件驱动（长、慢、但像真的）：**

```python
from qd.backtest import Backtest, BacktestConfig
from qd.strategy.builtin import sma_cross
from qd.data.synthetic import generate_demo_market
from qd.metrics.perf import perf_report

md = generate_demo_market(n_symbols=50, start="2018-01-01", end="2024-12-31", seed=7)

strategy = sma_cross(fast=20, slow=60)
cfg = BacktestConfig(
    initial_cash=1_000_000,
    commission=0.0003,          # 视交易所而定
    slippage=0.0010,
    exec_price="next_open",     # 次日开盘成交
)
res = Backtest(md, strategy, cfg).run()

print(res.summary())
print("成交笔数:", len(res.trades))
print("绩效:", perf_report(res.equity, rf=0.02))
```

我实跑的结果（事件驱动那段）：

```
成交笔数: 8510
绩效: PerfReport(sharpe=0.2422, annual=0.048055, n_fields=21)
```

**8510 笔成交、夏普 0.24、年化 4.81%**——和 01-01 里那个"双均线 8418 笔、年化 3.36%"几乎一样，只是成本和成交价假设略不同。**这说明向量化和事件驱动在"简单策略 + 简单成本"上，结论是接近的。**

> **但真正的差别不在这里，在"你能问什么"。**
> 向量化那张表能告诉你"夏普 0.24"；
> 事件驱动能告诉你"这 8510 笔里，有多少笔是因为涨停没买进、多少笔滑点超了 10 bp"。
> **后者才是实盘会问的问题。**

`res.equity` 是净值曲线，`res.trades` 是逐笔成交，`res.positions` 是持仓序列——**三者齐全才能做完整的绩效与成本分析**（06-04）。

## 五、共同的陷阱：那个 `shift(1)`

两种实现都会栽在同一个地方——**对齐**。

向量化里，`signal.shift(1) * ret` 的这一行是命门：

> **去掉 `shift(1)`，就变成"用当天收盘算的信号 × 当天的收益"**，
> 等于假设你能在"知道收盘价之后、回到收盘之前"下单。
> **这就是 02-04 讲的前视偏差，而且它会给你一条非常漂亮的曲线。**

事件驱动里同样有这个问题，只是藏得更深：如果你在 `exec_price="close"` 的配置下用当日收盘信号，陷阱和向量化一模一样。

> ⚠️ **一个可以自查的规则：信号与成交至少要隔一个 bar。**
> 06-02 会讲得更细（开盘成交、收盘成交、VWAP 的差别）；
> 但记住这句就够防住 80% 的事故。

## 六、两者怎么选

| 你的情况 | 选哪个 |
| --- | --- |
| 因子研究、参数扫描、横截面选股 | **向量化**（快，够用） |
| 有止损/加减仓/仓位状态 | **事件驱动** |
| 要精确模拟涨跌停、部分成交 | **事件驱动** |
| 准备上实盘 | **事件驱动**（最好与实盘同引擎） |
| 只想快速验证一个想法 | 向量化先跑，别急着工程化 |

> **最务实的做法是"两段式"：**
> **向量化做筛选**（一天跑几百个因子），**事件驱动做确认**（挑出来的那几个，认真跑一遍）。
> 前者负责"广度"，后者负责"真实"——正好对应 01-05 讲的 IC 与 √BR。

## 七、把这一篇串起来

回到 Zipline 那句 README。

它选择了一条更慢的路——因为它要回答的问题不是"这个想法历史表现如何"，而是"**如果我真的这么下单，会发生什么**"。

> 这两个问题，恰好是 06 章的两半：
> 前半（06-02 ~ 06-06）在问"数字可不可信"；
> 后半（06-07）在问"能不能兑现"。
> **而向量化 vs 事件驱动，就是这两半的工程分界线。**

> 一句话收尾：
> **向量化让回测变快，事件驱动让回测变真。**
> 快能帮你多试几个想法，真能帮你少亏几次钱——
> **而这两件事，恰恰不能同时兼得。**
