# 回测的两种实现

回测（backtest）是用历史数据模拟策略执行的过程。工程上有两种截然不同的实现方式：**向量化回测**与**事件驱动回测**。理解它们的差异，是判断一个回测结果可信度的第一步。

## 一、向量化回测

向量化回测把整个回测看作一系列矩阵运算。核心数据结构是 `dates × symbols` 的二维表：

- 价格面板 $P_{t,i}$
- 信号面板 $S_{t,i}$（目标仓位或目标权重）
- 收益面板 $r_{t,i}$

组合收益直接由信号与收益的逐元素乘积得到：

$$ r_{p,t} = \sum_{i} w_{i,t} \cdot r_{i,t+1} $$

其中关键是**信号在 $t$ 生成，收益取 $t+1$**，即 $w_{i,t}$ 与 $r_{i,t+1}$ 对齐。写成 pandas 就是 `weights.shift(1) * returns` 或 `weights * returns.shift(-1)`（两者等价，但必须选一个并写清楚）。

**优点**：

- 极快，百万级数据点在秒级完成，适合参数扫描与因子研究；
- 代码短，逻辑清晰，易于审查；
- 天然支持横截面运算（排序、分组、标准化）。

**缺点**：

- 难以表达路径依赖：止盈止损、逐笔成交、资金约束、已有的持仓状态都很难写进矩阵；
- 成交假设隐含且粗糙：默认"以收盘价全部成交"；
- 无法模拟订单的排队、部分成交、撤单。

因此向量化回测最适合**横截面选股类策略**（[多因子选股](../07-策略/07-04-多因子选股.md)、[截面动量与反转](../07-策略/07-03-截面动量与反转.md)），以及因子检验（[分层回测](../05-因子/05-06-分层回测.md)）。

### 向量化示例

```python
import numpy as np
import pandas as pd
from qd.data.synthetic import generate_demo_market
from qd.metrics.perf import perf_report

md = generate_demo_market(n_symbols=50, start="2018-01-01", end="2024-12-31", seed=7)
close = md.close()

# 1) 信号：20 日均线上穿 60 日均线 → 目标权重 1，否则 0
ma_fast = close.rolling(20).mean()
ma_slow = close.rolling(60).mean()
signal = (ma_fast > ma_slow).astype(float)

# 2) 关键对齐：t 日信号，对应 t+1 日收益
ret = close.pct_change()
port_ret = (signal.shift(1) * ret).mean(axis=1)   # 组合等权

# 3) 绩效
nav = (1 + port_ret.fillna(0)).cumprod()
print(perf_report(nav, rf=0.02))
```

注意 `signal.shift(1)` 这一行——去掉它，回测就会用"当天的收盘信号 × 当天的收益"，得到虚假的高收益。这是向量化回测最常见的错误。

## 二、事件驱动回测

事件驱动回测模拟一个真实的交易循环，按时间逐个事件推进：

```
for each bar in timeline:
    1. 接收行情（bar）
    2. 策略计算目标仓位 → 生成订单
    3. 撮合引擎按成交假设撮合（价格、滑点、成交量限制）
    4. 更新持仓、现金、组合市值
    5. 记录当期状态
```

核心数据结构是一组**可变状态**：现金、持仓字典、订单队列、成交记录。

**优点**：

- 可以精确表达成交假设：次日开盘成交、VWAP、限价单、涨跌停不可成交、部分成交（[撮合滑点与成交假设](../06-回测/06-02-撮合滑点与成交假设.md)）；
- 天然支持路径依赖：止损、加仓减仓、资金约束、保证金；
- 输出的 `trades` 记录可逐笔审查，便于排查问题。

**缺点**：

- 慢，Python 循环是瓶颈；
- 代码量大，状态管理复杂，容易引入 bug；
- 并行化不如向量化容易。

事件驱动最适合**时序策略**（[趋势跟踪](../07-策略/07-01-趋势跟踪.md)、[配对交易](../07-策略/07-05-配对交易与统计套利.md)）、需要止盈止损或复杂撮合的策略，以及一切**准备上实盘**的策略。

### 事件驱动示例

```python
from qd.backtest import Backtest, BacktestConfig
from qd.strategy.builtin import sma_cross
from qd.data.synthetic import generate_demo_market
from qd.metrics.perf import perf_report

md = generate_demo_market(n_symbols=50, start="2018-01-01", end="2024-12-31", seed=7)

strategy = sma_cross(fast=20, slow=60)
cfg = BacktestConfig(
    initial_cash=1_000_000,
    commission=0.0003,          # 视具体交易所/数据源而定
    slippage=0.0010,
    exec_price="next_open",     # 次日开盘成交
)
bt = Backtest(md, strategy, cfg)
res = bt.run()

print(res.summary())
print("净值尾部:", res.equity.tail())
print("成交笔数:", len(res.trades))
print("绩效:", perf_report(res.equity, rf=0.02))
```

`res.equity` 是净值曲线，`res.trades` 是逐笔成交，`res.positions` 是持仓序列，`res.summary()` 给出汇总。三者齐全才能做完整的绩效与成本分析（[绩效指标全家桶](../06-回测/06-04-绩效指标全家桶.md)）。

## 三、两者怎么选

| 维度 | 向量化 | 事件驱动 |
| --- | --- | --- |
| 速度 | 快（秒级） | 慢（分钟级） |
| 代码量 | 几十行 | 上百行 |
| 成交假设 | 隐含、粗糙 | 显式、可控 |
| 路径依赖 | 难表达 | 自然支持 |
| 输出粒度 | 净值曲线为主 | 逐笔成交 + 持仓 |
| 适用场景 | 因子研究、参数扫描、横截面选股 | 时序策略、止盈止损、实盘前验证 |

**实务建议：两者都要做，向量化在前，事件驱动在后。** 先用向量化快速筛选候选（因子是否有效、参数大致范围），再用事件驱动对少数幸存者做严格验证（成本、容量、成交可行性）。若两者结果差异巨大，说明向量化阶段的假设过于乐观，应当以事件驱动为准。

## 四、共同的陷阱

两种实现都会踩的坑：

1. **前视偏差**：向量化体现在 `shift` 方向，事件驱动体现在"用当日收盘价生成信号又按当日收盘成交"（[前视偏差的十种来源](../06-回测/06-03-前视偏差的十种来源.md)）。
2. **幸存者偏差**：股票池只含当前存续标的，历史退市股被系统性剔除。
3. **成本假设缺失**：向量化回测默认零成本，事件驱动若 `slippage=0` 也等于零成本。
4. **过拟合**：向量化的高速使参数扫描变得廉价，也更容易过拟合（[过拟合与多重检验](../06-回测/06-05-过拟合与多重检验.md)）。

## 常见坑

1. **`shift` 方向写反**：这是向量化回测的头号 bug，表现为收益高得不真实。
2. **用 `fillna(0)` 掩盖停牌**：停牌日收益应为 NaN 且持仓不变，填 0 会伪造一条平滑的净值。
3. **等权组合的收益算错**：`(signal.shift(1) * ret).mean(axis=1)` 假设每期都把资金平分给所有持仓；若信号稀疏，实际权重是 $1/\text{持仓数}$ 而非 $1/N$，两者不同。
4. **事件驱动里用未来 bar**：在 `on_bar` 中访问 `data.iloc[i+1]`，或在信号里用了当日收盘价却按当日收盘成交。
5. **忽略分红与复权**：用未复权价回测，除权日会出现假暴跌。
6. **只看净值不看成交**：事件驱动下若不检查 `res.trades`，可能发现策略是靠几笔异常成交赚钱的。
