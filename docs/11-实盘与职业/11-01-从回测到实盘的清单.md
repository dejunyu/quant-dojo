# 从回测到实盘的清单

回测赚钱、实盘亏钱，是量化新人最常遇到的打击。原因通常不是策略错了，而是**回测里省略了现实**。这一篇把从回测到实盘的缺口整理成 30 项检查，分成六个维度。上线前逐项打勾，能避开绝大多数低级但致命的事故。

## 维度一：数据（1-6）

| # | 检查项 | 防的是什么 |
| --- | --- | --- |
| 1 | 数据来源与实盘一致（同一供应商、同一复权方式） | 回测用后复权、实盘用不复权，价格对不上 |
| 2 | 无幸存者偏差：历史股票池包含已退市/被 ST 的标的 | 回测收益虚高，实盘买到垃圾股 |
| 3 | 财务数据用"当时可得版本"而非最终修订版 | 前视偏差 |
| 4 | 处理了停牌、涨跌停、新股上市首日、长期停牌复牌 | 回测假设能成交，实盘不能 |
| 5 | 交易日历与交易所一致（含临时休市） | 非交易日产生虚假信号 |
| 6 | 数据管道有自动校验：缺失率、异常值、价格跳变告警 | 脏数据直接进策略，静默亏钱 |

## 维度二：成本与容量（7-12）

| # | 检查项 | 防的是什么 |
| --- | --- | --- |
| 7 | 滑点按市值/流动性分层设定，而非全市场统一 5bps | 小盘股实际滑点可达 50bps+ |
| 8 | 冲击成本按 [参与率模型](../09-执行与成本/09-03-冲击成本模型.md) 动态计算 | 规模一大收益消失 |
| 9 | 佣金、印花税、过户费、融资利率全部计入 | 成本被系统性低估 |
| 10 | 股息与红利税（持股期 <1 个月按 20%）已建模 | 高换手策略额外损失 |
| 11 | 容量估算：按可承受成本反推最大管理规模 | 募资超出策略容量 |
| 12 | 换手率在扣成本后仍为正收益 | 策略只在零成本假设下赚钱 |

## 维度三：信号与模型（13-18）

| # | 检查项 | 防的是什么 |
| --- | --- | --- |
| 13 | 信号严格滞后：用 $t$ 日收盘算，$t+1$ 日成交（`t_plus_1=True`） | 前视偏差 |
| 14 | 用 [净化 K 折或 walk-forward](../10-机器学习/10-03-金融数据的交叉验证.md) 评估，非随机 K 折 | 交叉验证泄漏 |
| 15 | 参数敏感性检查：最优参数处于"高原"而非"尖峰" | 过拟合 |
| 16 | 计算 [deflated Sharpe](../10-机器学习/10-05-过拟合可解释与模型监控.md)，考虑试验次数 | 多重检验偏差 |
| 17 | 样本内外夏普衰减 < 50% | 过拟合 |
| 18 | 收益不集中在少数几天/几只股票（检查贡献分布） | 伪信号 |

## 维度四：执行（19-23）

| # | 检查项 | 防的是什么 |
| --- | --- | --- |
| 19 | 订单类型与成交假设一致（限价单需建模成交概率） | 回测假设全成交 |
| 20 | 大单拆分与 [参与率控制](../09-执行与成本/09-02-算法交易TWAP与VWAP.md) | 冲击成本失控 |
| 21 | 下单幂等（客户端订单号去重）+ 超时重试策略 | 重复下单、仓位翻倍 |
| 22 | 断线重连后有持仓与订单对账（reconciliation） | 本地状态与真实不一致 |
| 23 | 交易时段与集合竞价规则正确处理 | 无效报单 |

## 维度五：风控与监控（24-28）

| # | 检查项 | 防的是什么 |
| --- | --- | --- |
| 24 | 风控前置且独立于策略进程（资金、持仓、集中度、流速、净值五层） | 策略 bug 导致巨额亏损 |
| 25 | 单票/行业/总杠杆/净敞口硬上限已配置并测试过 | 黑天鹅暴露 |
| 26 | 回撤熔断阈值与恢复条件已写死 | 事中犹豫 |
| 27 | 三层监控就绪：输入 PSI、输出分布、实盘表现 | 事后才发现失效 |
| 28 | 下线标准预先写死并自动化执行 | 拒不认错、持续亏损 |

## 维度六：运维与预案（29-30）

| # | 检查项 | 防的是什么 |
| --- | --- | --- |
| 29 | 全链路日志（行情、信号、订单、回报、风控拒绝）可审计、可复现 | 事后无法归因 |
| 30 | 失败预案已演练：行情断、柜台断、主机宕机、数据错误、极端行情 | 手忙脚乱、错误处置 |

## 一、按收益漏损排序：哪里最贵

经验上，从回测到实盘的收益漏损（按常见量级排序）：

1. **成本**（20%~60% 的毛收益）：滑点、冲击、税。规模越大越严重。
2. **前视与泄漏**（10%~40%）：用当日收盘成交、用修订后财务数据、随机 K 折。
3. **执行退化**（10%~30%）：限价单不成交、大单冲击、延迟。
4. **容量约束**（0%~50%）：小资金能做的策略，大资金做不了。
5. **非平稳与漂移**（随时间累积）：因子失效、市场结构变化。

**最省钱的顺序是先查 1 和 2**——它们最容易修，也最常被忽略。

## 二、三阶段放量

不要一次性上满仓。标准流程：

### 阶段 1：模拟盘（paper trading，建议 1~3 个月）

- 用**实时行情**驱动，但不下真实订单（或下极小量订单）。
- 记录每个信号、假设成交价、真实可得价格。
- 通过条件：模拟盘与回测的**日收益相关系数 > 0.7**，且累计偏差 < 10%。

这一阶段唯一目的是**检验数据管道与回测一致性**。若模拟盘与回测对不上，说明回测有 bug，不要进入下一阶段。

### 阶段 2：小资金（建议 3~6 个月，资金为目标的 5%~10%）

- 真实成交，接受真实成本。
- 重点核对：实际滑点 vs 假设滑点、实际成交率、实际换手。
- 通过条件：
  - 实盘夏普 ≥ 回测夏普的 60%。
  - 实际滑点在假设的 1.5 倍以内。
  - 无重大事故（错单、断线未处理、风控失效）。

### 阶段 3：满仓

- 按容量上限分批放量，每批间隔 1 个月观察。
- 放量时同步更新 [冲击成本假设](../09-执行与成本/09-03-冲击成本模型.md)，因为规模变大后成本参数会变。

## 三、上线后的日常

- **每日**：成交与滑点统计、异常单笔复盘、持仓与对账。
- **每周**：[成本归因](../09-执行与成本/09-05-交易成本归因.md) 按维度聚合、与回测净值对比。
- **每月**：PSI 漂移检查、滚动 IC、策略表现复核、容量重估。
- **每季**：全参数重估、下线标准复核、预案演练。

## 四、代码示例

```python
import numpy as np
import pandas as pd
from qd.data.synthetic import generate_demo_market
from qd.backtest import Backtest, BacktestConfig
from qd.strategy.builtin import factor_long_only
from qd.optimize import purged_kfold
from qd.metrics.perf import (perf_report, sharpe, deflated_sharpe,
                             probabilistic_sharpe, max_drawdown)

md = generate_demo_market(n_symbols=100, start="2018-01-01", end="2024-12-31", seed=7)
strat = factor_long_only(factors=["mom_12_1"], top_k=20, rebalance="1M")

# ---- 检查 7/8/9：成本按规模分层设定，小资金与大资金分别回测 ----
def run(initial_cash, slippage_bps):
    cfg = BacktestConfig(initial_cash=initial_cash, commission_rate=0.0003,
                         slippage_bps=slippage_bps, stamp_tax=0.0005,
                         allow_short=False, t_plus_1=True)   # 检查 13：T+1 成交
    return Backtest(md, strat, cfg).run()

small = run(1_000_000, 10)      # 小资金：滑点 10bps
large = run(100_000_000, 40)    # 大资金：冲击显著，滑点 40bps
for tag, r in [("小资金", small), ("大资金", large)]:
    eq = r.equity.pct_change().dropna().values
    print("%s 夏普 %.2f 最大回撤 %.2f%%" % (tag, sharpe(eq), max_drawdown(r.equity.values)*100))

# ---- 检查 14/15：净化切分 + 参数高原 ----
rets = md.returns().dropna()
folds = purged_kfold(len(rets), n_splits=5, horizon=20, embargo=5)
print("净化折数:", len(folds))

for top_k in [10, 20, 30, 40]:                       # 参数敏感性：应为高原
    r = Backtest(md, factor_long_only(factors=["mom_12_1"], top_k=top_k,
                                      rebalance="1M"),
                 BacktestConfig(initial_cash=10_000_000, commission_rate=0.0003,
                                slippage_bps=20, stamp_tax=0.0005)).run()
    print("top_k=%2d 夏普 %.2f" % (top_k, sharpe(r.equity.pct_change().dropna().values)))

# ---- 检查 16/17：多重检验修正与样本内外落差 ----
cut = int(len(rets) * 0.7)
eq = large.equity.pct_change().dropna().values
sr_in, sr_out = sharpe(eq[:cut]), sharpe(eq[cut:])
print("样本内 %.2f 样本外 %.2f 衰减 %.1f%%" % (sr_in, sr_out, 100*(1-sr_out/sr_in)))
dsr = deflated_sharpe(np.array([sr_out]), n_trials=50, n_obs=len(eq[cut:]),
                      skew=float(pd.Series(eq[cut:]).skew()),
                      kurt=float(pd.Series(eq[cut:]).kurt()))
print("Deflated Sharpe:", np.round(dsr, 3))
print(perf_report(large.equity))
```

## 常见坑

- **跳过分阶段直接满仓**：一次性把三个月才能发现的问题放大成不可逆损失。
- **只检查收益不检查成交**：模拟盘最容易造假的地方就是"假设成交"。
- **上线后再定下线标准**：事到临头一定舍不得砍。必须在上线前写死。
- **回测参数与实盘参数不一致**：代码里两套参数是最隐蔽的 bug 来源，应共用一份配置。
- **不记录试验次数**：事后无法算 deflated Sharpe，也无法判断过拟合程度。
- **忽略心理因素**：实盘连续亏损三个月时，能不能坚持不下线、也不擅自改参数？这需要事先的书面纪律。
