# 实盘延迟与系统

回测是"上帝视角"：你看到收盘价、瞬间按收盘价成交、零延迟、零故障。实盘是一条有延迟、会丢包、会宕机的物理链路。本节把这条链路拆开，并给出在回测中保守模拟的方法。

## 一、完整链路与延迟构成

一次交易的时间线：

$$\underbrace{t_0}_{\text{市场成交}} \to \underbrace{t_1}_{\text{行情到你}} \to \underbrace{t_2}_{\text{计算信号}} \to \underbrace{t_3}_{\text{订单到交易所}} \to \underbrace{t_4}_{\text{撮合回报}}$$

| 环节 | 典型延迟 | 说明 |
| --- | --- | --- |
| 行情快照/逐笔推送 | 毫秒~秒级（Level-1 快照常 3 秒一次） | 券商的 Level-1 行情是**快照**而非逐笔，你看到的"最新价"可能已过时 |
| 网络传输 | 1~50 ms（同城机房更低） | 跨省、跨运营商、Wi-Fi 都会放大 |
| 策略计算 | 微秒~秒 | 取决于模型复杂度与是否向量化 |
| 风控检查 | 1~10 ms | 前置风控是必需的，见下文 |
| 下单到交易所 | 1~50 ms | 柜台系统排队 |
| 撮合与回报 | 1~10 ms | 回报回程还有一次延迟 |

对**日频策略**，这些延迟（合计 < 1 秒）几乎无影响；对**分钟级策略**开始有影响；对**秒级及以下策略**，延迟就是全部——这时需要托管（colocation）、直连（DMA）、FPGA 等基础设施投入。

**关键认知**：延迟本身不是问题，**"你以为的价格"与"成交时的价格"不一致**才是问题。这个差值就是 [时机成本](09-05-交易成本归因.md) 的物理来源。

## 二、行情延迟的两种形态

1. **延迟（latency）**：数据是过去的。回测中用"信号在 $t$ 产生、交易在 $t+k$ 执行"建模。
2. **缺失（gap）**：数据根本没到。断线、丢包、交易所停牌。回测中几乎不建模，实盘中必须处理。

必须区分**快照行情**与**逐笔行情**：Level-1 快照每 3 秒左右推送一次，你看到的最新价可能落后 3 秒，且盘口深度是采样的。用快照行情做高频策略是灾难。

## 三、下单链路与工程要求

### 1. 幂等下单

网络超时是最常见的故障：你不知道订单是"没发出"还是"发了但回报丢了"。解决方案是**客户端订单号（clOrdId）幂等**：

- 每次下单生成唯一 ID，重试时复用同一 ID。
- 交易所/柜台按 ID 去重，保证不会重复成交。
- 这是防止"重试导致双倍仓位"的唯一可靠手段。

### 2. 风控前置

风控必须在**策略进程之外**、在**订单发出之前**执行，且独立于策略代码。分层：

| 层级 | 检查项 | 失败动作 |
| --- | --- | --- |
| 语法层 | 价格/数量合规、涨跌停价内、最小变动价位 | 拒绝 |
| 账户层 | 可用资金、可用持仓、可用融资额度 | 拒绝或缩减 |
| 组合层 | 单票集中度、行业集中度、总杠杆、净敞口 | 拒绝或缩减 |
| 流速层 | 每秒订单数、每分钟撤单数、当日累计成交额 | 熔断暂停 |
| 净值层 | [回撤熔断](../08-组合与风险/08-05-止损与回撤控制.md) | 平仓并告警 |

风控前置的意义：**策略代码可以有 bug，风控必须独立于它**。历史上多次"乌龙指"事件（如 2013 年光大证券事件）都是策略或下单系统缺陷叠加风控缺位造成的。

### 3. 断线重连与状态恢复

- **心跳与看门狗**：策略进程定期写心跳，监控进程发现超时则告警/重启。
- **重连后的状态对账**：重连后必须先用查询接口拉取**当前真实持仓与未成交订单**，重建本地状态，而不是假设内存中的状态正确。这一步叫 **reconciliation**，是实盘系统最容易出错的地方。
- **未知订单处理**：对于"发出但不知结果"的订单，先查询状态，再决定撤单或等待，绝不重复下单。
- **优雅降级**：行情断了应停止开新仓（不能盲目下单），但不一定要立即平仓（要看策略类型与风险敞口）。

### 4. 日志与审计

- 所有订单、回报、风控拒绝、异常都要落盘，带毫秒级时间戳与序列号。
- 日志是事后归因与合规审计的唯一依据（见 [从回测到实盘的清单](../11-实盘与职业/11-01-从回测到实盘的清单.md)）。
- 建议逐笔落盘原始报文，便于复现。

## 四、回测里如何保守模拟延迟

三条必须遵守的规则：

### 规则 1：信号与成交必须错期

**信号用第 $t$ 日收盘价计算，交易在第 $t+1$ 日执行。** 这是最低要求。更严格的是假设在 $t+1$ 日的**开盘价或 VWAP** 成交，而非收盘价。

在 `qd.backtest` 中，`BacktestConfig(t_plus_1=True)` 就是这一约束的开关。

### 规则 2：价格劣化

不要用"信号价"成交，用"信号价 + 滑点"：

$$P_{fill} = P_{signal}\times(1 + s\cdot\text{side})$$

其中 $s$ 为滑点（买入为正）。日频 A股策略建议：

| 标的 | 保守滑点 |
| --- | --- |
| 沪深 300 成分 | 5~10 bps |
| 中证 500 成分 | 10~20 bps |
| 小市值/低流动性 | 30~100 bps |

再叠加 [冲击成本](09-03-冲击成本模型.md)（按参与率动态计算），才是完整的成本假设。

### 规则 3：注入延迟与故障

- **延迟模拟**：把信号生效时间后移 $k$ 根 K 线（日频取 $k=1$，分钟级取 $k=1\sim3$）。
- **成交概率模拟**：限价单不应假设 100% 成交。可以按"该分钟是否有成交触及你的限价"来判定。
- **故障模拟**：随机丢弃若干交易日的订单（模拟断线），看净值影响。
- **容量模拟**：按参与率上限截断成交量，超过部分不成交。

## 五、代码示例

```python
import numpy as np
from qd.data.synthetic import generate_demo_market
from qd.backtest import Backtest, BacktestConfig
from qd.strategy.builtin import sma_cross
from qd.utils.calendar import trading_days
from qd.metrics.perf import sharpe, annual_return, max_drawdown

md = generate_demo_market(n_symbols=30, start="2018-01-01", end="2024-12-31", seed=7)

# 校准：确认回测使用的交易日历与实盘一致
cal = trading_days("2018-01-01", "2024-12-31", market="A")
print("交易日数 %d，数据日期数 %d" % (len(cal), len(md.dates)))

scenarios = {
    "乐观(当日收盘价成交, 5bps)": dict(slippage_bps=5),
    "中性(次日成交, 20bps)":      dict(slippage_bps=20),
    "保守(次日成交, 50bps)":      dict(slippage_bps=50),
}
for name, kw in scenarios.items():
    cfg = BacktestConfig(initial_cash=1_000_000, commission_rate=0.0003,
                         stamp_tax=0.0005, allow_short=False,
                         t_plus_1=True, **kw)   # t_plus_1=True 即为"信号次日成交"
    res = Backtest(md, sma_cross(fast=10, slow=60), cfg).run()
    r = res.equity.pct_change().dropna().values
    print("%-28s 年化=%6.2f%% 夏普=%.2f 回撤=%6.2f%%"
          % (name, annual_return(r)*100, sharpe(r), max_drawdown(res.equity.values)*100))

# 故障模拟：随机 2% 的交易日不下单（模拟断线），评估净值影响
r = res.equity.pct_change().dropna().values
rng = np.random.default_rng(7)
mask = rng.random(len(r)) < 0.02     # 断线日当天无法交易，收益记 0
r_gap = np.where(mask, 0.0, r)
print("断线 2%% 交易日后: 年化 %6.2f%% → %6.2f%%"
      % (annual_return(r)*100, annual_return(r_gap)*100))
```

## 常见坑

- **回测用当日收盘价成交**：几乎一定包含前视，是回测虚高的头号原因。
- **忽略 Level-1 快照的 3 秒间隔**：用快照数据做分钟级回测会显著高估成交概率。
- **没有幂等 ID**：网络重试造成重复下单，仓位翻倍，是实盘事故的经典成因。
- **风控写在策略进程里**：策略崩溃时风控一起崩溃。
- **重连后不复盘对账**：本地状态与真实持仓不一致，接下来的所有决策都是错的。
- **只用回测最优参数上线**：参数应在 [净化交叉验证](../10-机器学习/10-03-金融数据的交叉验证.md) 下选择，并对延迟做敏感性分析。
- **忽略交易所的时间规则**：集合竞价时段、收盘前不可撤单时段、隔夜委托的生效时点。
