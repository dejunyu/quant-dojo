# 订单类型

策略信号给出的是"想要什么仓位"，订单类型决定"怎么把这笔仓位拿到手"。同一信号用不同订单执行，实盘收益可以相差一个数量级。本节系统梳理主流订单类型及其成交逻辑。

## 一、价格优先、时间优先：理解撮合是前提

交易所撮合遵循两条原则：

1. **价格优先**：更高买价、更低卖价优先成交。
2. **时间优先**：同价格下，先到的订单优先。

订单簿（order book）分为买盘（bid）与卖盘（ask），买一卖一之间的差即为**买卖价差（spread）**：

$$\text{spread} = P_{ask1} - P_{bid1},\qquad \text{mid} = \frac{P_{ask1}+P_{bid1}}{2}$$

**价差是你为"立即成交"支付的费用**。你用市价单买入，成交在卖一，相对中间价立刻损失半个价差（half-spread）。对高频策略而言，这个成本往往大于全部预期收益。

## 二、主要订单类型

| 订单类型 | 成交逻辑 | 保证 | 典型用途 |
| --- | --- | --- | --- |
| **市价单（MKT）** | 与对手方最优价及后续档位逐档成交，直到数量满足 | 保证成交（有对手盘时），不保证价格 | 抢筹、紧急离场、止损 |
| **限价单（LMT）** | 只在指定价格或更优价格成交，未成交部分挂单等待 | 保证价格，不保证成交 | 被动成交、控成本、做市 |
| **止损单（STP）** | 股价触及触发价后转为市价单 | 触发后保证成交，价格不定 | 风控离场 |
| **止损限价单（STL）** | 触及触发价后转为限价单 | 保证价格上限，可能完全不成交 | 风控但避免跳空成交 |
| **冰山单（Iceberg）** | 只披露总委托量的一部分，成交后再自动补充 | 隐藏真实意图 | 大单拆分、减小冲击 |
| **FOK** | Fill-or-Kill：要么全部立即成交，要么整单撤销 | 全有或全无 | 套利、必须凑齐的组合交易 |
| **IOC** | Immediate-or-Cancel：立即成交可成交部分，剩余撤销 | 部分成交，不留挂单 | 扫单、机会性成交 |

### 市价单

- 优点：几乎一定成交，执行确定性最高。
- 缺点：**价格完全不可控**。在薄盘口或涨跌停附近，市价单会一路扫过多个价位，实际成交均价可能远离你看到的报价。A股还有"价格笼子"约束（科创板/创业板限价申报偏离基准价不得超过 2%），市价单同样受保护机制限制。

### 限价单

- 挂在买一（或更低）等待成交：赚价差，但可能长期不成交，产生**机会成本与逆向选择**。
- **逆向选择（adverse selection）是限价单的核心风险**：你的限价单成交，通常意味着价格正在朝不利方向移动。这一效应在微观结构文献中被广泛讨论（Copeland 与 Galai 关于价差中的信息成分、Glosten 与 Milgrom 的序贯交易模型），实务中常称为"成交即亏损"。
- 变体：**隐藏单（Hidden）**、**冰山单**、**只做 maker 的单（Post-only，若会立即成交则自动撤销）**。

### 止损单与止损限价单

止损单在触发后变成市价单，因此：

- 在正常行情下，成交价接近触发价。
- 在**跳空低开**时，成交价可能远低于触发价。比如触发价 10 元，次日直接低开到 9 元，止损单在 9 元附近成交——滑点 10%。
- 止损限价单在触发后挂出限价单，避免了跳空成交，但**可能完全不成交**，风险敞口继续暴露。这是"确定性 vs 价格"的取舍。

在 A股，跌停封板时**两者都无法成交**，必须等打开跌停。因此 [止损](../08-组合与风险/08-05-止损与回撤控制.md) 的回测必须包含不可成交情形。

### FOK 与 IOC

二者的区别只在"部分成交时的处理"：

- FOK：若不能一次全成，整单撤销。适合必须完整成交的场景（如 ETF 一篮子申赎、配对交易双腿）。
- IOC：成多少算多少，剩余立刻撤销，不留挂单。适合扫掉当前可见流动性，避免自己的挂单成为他人信息。

### 冰山单

总委托量 $Q$，每次只显示 $q$（$q \ll Q$），成交后自动补充至 $q$。目的是**隐藏真实意图，减少市场冲击**。缺点是：暴露的订单被反复成交本身会泄露信息（"冰山探测"是做市商的标准技术），且有些交易所对冰山单有最低披露比例要求。

## 三、场景选择指南

| 场景 | 推荐订单 | 理由 |
| --- | --- | --- |
| 信号刚触发、需抢筹 | 限价略优于对手价，或 IOC | 避免市价扫盘 |
| 不急于成交、控成本 | 限价挂在买一 | 赚价差 |
| 大单（占日成交量 > 5%） | 冰山 + [TWAP/VWAP 算法](09-02-算法交易TWAP与VWAP.md) | 减小冲击 |
| 组合必须双腿齐备 | FOK | 避免单边风险 |
| 风控离场、盘中 | 止损限价 | 兼顾确定性与价格 |
| 隔夜/跳空风险 | 无法用订单解决，需降仓位 | 订单在跳空面前无效 |
| 涨跌停封板 | 排队等待或次日处理 | 无法强制成交 |

## 四、代码示例

```python
from qd.data.synthetic import generate_demo_market
from qd.backtest import Backtest, BacktestConfig
from qd.strategy.builtin import sma_cross

md = generate_demo_market(n_symbols=30, start="2018-01-01", end="2024-12-31", seed=7)

# 回测中订单类型被抽象为：成交价 = 信号价 + 滑点（按 bps 计）
# 市价单：滑点 = 半个价差 + 冲击；限价单：若能成交则滑点为 0 或负
aggressive = BacktestConfig(initial_cash=1_000_000, commission_rate=0.0003,
                            slippage_bps=10, stamp_tax=0.0005,   # 市价/激进
                            allow_short=False, t_plus_1=True)
passive = BacktestConfig(initial_cash=1_000_000, commission_rate=0.0003,
                         slippage_bps=0, stamp_tax=0.0005,        # 限价/被动
                         allow_short=False, t_plus_1=True)

for name, cfg in [("激进(市价)", aggressive), ("被动(限价)", passive)]:
    res = Backtest(md, sma_cross(fast=10, slow=60), cfg).run()
    print("%s 最终净值 %.3f  交易笔数 %d"
          % (name, res.equity.iloc[-1], len(res.trades)))
```

这里的 `slippage_bps` 就是订单类型的**成本代理**：激进订单用较大滑点，被动订单用较小滑点但需另行建模成交概率与机会成本。回测若忽略成交概率，会系统性高估限价单的收益。

## 常见坑

- **回测里默认全部成交**：限价单不成交是常态，尤其在快速上涨行情中。忽略它等于免费获得流动性。
- **市价单在薄盘口被扫**：回测用收盘价成交，实盘用市价会滑出几个价位。用 `slippage_bps` 保守设定（小盘股 20~50bps）。
- **止损单当成"保证止损价"**：它只在连续行情下近似成立，跳空时完全失效。
- **冰山单被探测**：隐藏量比例过低反而暴露意图。
- **FOK 在流动性不足时频繁撤销**：会导致信号无法实现，实盘收益与回测严重不符。
- **忽略订单的费用差异**：部分市场对 maker（挂单）返佣、taker（吃单）收费，这会改变订单选择的经济性。
