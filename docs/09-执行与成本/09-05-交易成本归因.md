# 交易成本归因

回测假设你能在收盘价成交、零冲击、零延迟。实盘三者都不成立。**成本归因**就是把"回测净值与实盘净值之间的差额"系统地拆开，找出钱到底花在哪——这是从回测走向稳定盈利的关键一步（见 [从回测到实盘的清单](../11-实盘与职业/11-01-从回测到实盘的清单.md)）。

## 一、基准价的选择

所有成本都是相对某个基准而言的，选错基准会得到错误的结论。

| 基准 | 定义 | 衡量的是什么 | 适用 |
| --- | --- | --- | --- |
| **决策价 $P_{dec}$** | 信号产生时刻的中间价 | 全部实现落差（IS） | 衡量策略到执行的完整漏损 |
| 到达价 $P_{arr}$ | 订单进入市场时刻的中间价 | 纯执行质量 | 衡量算法/交易员 |
| 开盘价 | 当日第一笔成交价 | 隔夜跳空 + 日内 | 隔夜持仓策略 |
| VWAP | 当日成交量加权价 | 相对市场平均的执行水平 | 被动大单 |
| 收盘价 | 当日收盘 | —— | **回测常用，但不该作为实盘归因基准** |

关键原则：**基准必须选在"你还无法行动"的时刻**。收盘价是在信号产生之后的未来信息，用它做基准会系统性低估成本（因为你不可能在收盘价成交）。决策价是唯一诚实的基准。

## 二、实现落差（IS）的完整分解

Perold (1988) 的经典框架。以买入方向为例（成本为正表示不利）：

$$\text{IS} = \frac{\bar P_{exec} - P_{dec}}{P_{dec}} \times \text{side}$$

逐层展开：

$$\text{IS} = \underbrace{\frac{P_{arr}-P_{dec}}{P_{dec}}}_{\text{延迟成本}} + \underbrace{\frac{\bar P_{exec}-P_{arr}}{P_{arr}}}_{\text{执行成本}} + \underbrace{\frac{P_{cancel}-P_{dec}}{P_{dec}}\cdot(1-f)}_{\text{未成交的机会成本}}$$

其中 $f$ 为成交比例，$P_{cancel}$ 为撤销时刻价格。执行成本再拆：

$$\text{执行成本} = \underbrace{\text{佣金}+\text{税}}_{\text{显性}} + \underbrace{\frac{\text{spread}}{2}}_{\text{价差}} + \underbrace{I_{perm}+I_{temp}}_{\text{冲击}}$$

冲击两项的建模见 [冲击成本模型](09-03-冲击成本模型.md)。

完整的四分量归因表：

| 分量 | 计算方式 | 典型量级（A股） | 可改进手段 |
| --- | --- | --- | --- |
| 佣金 | 成交额 × 费率 | 2~5 bps | 谈费率 |
| 印花税/过户费 | 卖出额 × 0.05% | 25 bps（摊到双边） | 降换手 |
| 价差 | 成交时的半价差 | 2~50 bps（小盘更宽） | 用限价单 |
| 冲击 | 相对到达价的移动 | $10^4\sigma\sqrt{Q/V}$ bps | 拆单、[POV 算法](09-02-算法交易TWAP与VWAP.md) |
| 延迟/时机 | $P_{arr}-P_{dec}$ | **波动大，常 > 冲击** | 缩短信号到下单链路 |
| 机会成本 | 未成交部分的后续走势 | 依完成率而定 | 提高完成率或改被动单 |

**时机成本是最容易被忽略、也往往是最大的一项**。它衡量的是"从信号产生到真正下单，价格已经走了多远"。日内策略中，如果信号在 10:00 产生、10:05 才下单，这 5 分钟的价格漂移就是纯漏损，与执行算法好坏无关。

## 三、归因的两个视角

### 1. 自上而下（top-down）

$$\text{归因缺口} = R_{backtest} - R_{live}$$

然后按"成本项总量"逐项扣减，看能否解释缺口。优点：直接与盈亏挂钩，管理层看得懂。缺点：无法定位到具体环节。

### 2. 自下而上（bottom-up）

对**每一笔成交**计算其相对决策价的滑点，再按维度聚合：

- 按订单类型（市价 / 限价 / IOC）
- 按参与率区间（<1%, 1-5%, >5% ADV）
- 按时间段（开盘 30 分钟 / 午间 / 尾盘）
- 按标的（市值分组、行业）
- 按算法（TWAP / VWAP / POV）
- 按方向（买 / 卖）

自下而上的价值在于**可行动**。典型的发现模式："尾盘 30 分钟的市价单平均滑点 42 bps，是全天其余时段的 3 倍"——这种结论直接对应一个改进动作。

## 四、实盘复盘方法

建议的复盘节奏与流程：

1. **每日**：统计当日成交笔数、完成率、总滑点（bps）、最大单笔滑点。异常单笔（> 100 bps）逐笔复盘。
2. **每周**：按上面 6 个维度做聚合表，与上周对比，识别结构性变化。
3. **每月**：与回测净值对比，计算归因缺口并逐项解释。若缺口中"未解释部分"持续超过 30%，说明回测模型有系统性错误（通常是成交假设或幸存者偏差）。
4. **每次规则变更/市场状态切换后**：重新标定滑点参数，更新回测中的 `slippage_bps`。

需要留意的**陷阱**：

- **幸存者偏差**：回测用的是当前存续标的，实盘会遇到退市、ST、停牌。
- **前视偏差**：回测用当日收盘价成交，实盘做不到。
- **成本参数过时**：冲击系数随市场波动率状态变化，需要滚动更新。
- **归因缺口被"运气"掩盖**：单月数据的随机性远大于成本差异，至少 3 个月数据才有统计意义。

## 五、代码示例

```python
import numpy as np
import pandas as pd
from qd.data.synthetic import generate_demo_market
from qd.backtest import Backtest, BacktestConfig
from qd.strategy.builtin import factor_long_only
from qd.metrics.perf import perf_report

md = generate_demo_market(n_symbols=50, start="2018-01-01", end="2024-12-31", seed=7)
cfg = BacktestConfig(initial_cash=10_000_000, commission_rate=0.0003,
                     slippage_bps=20, stamp_tax=0.0005,
                     allow_short=False, t_plus_1=True)
res = Backtest(md, factor_long_only(factors=["mom_12_1"], top_k=20, rebalance="1M"), cfg).run()
fills = res.fills.reset_index()          # 逐笔成交明细（含 date/side/price/qty）：归因的输入
trades = [{"symbol": r.symbol, "date": r.date, "price": r.price,
           "side": r.side, "shares": r.qty} for r in fills.itertuples()]

# ---- 自下而上归因：把每笔成交拆到四个分量 ----
close = md.close()
mid = close                             # 用收盘中间价近似决策价基准（实盘应为信号时刻价）

def attribute(trades, mid, commission_rate=0.0003, stamp_tax=0.0005, slippage_bps=20):
    rows = []
    for t in trades:                     # t 至少含 symbol/date/price/side/shares
        sym, d, px = t["symbol"], t["date"], t["price"]
        pdec = float(mid[sym].asof(pd.Timestamp(d)))     # 决策价基准
        side = 1 if t["side"] == "buy" else -1
        notional = px * t["shares"]
        # 1) 显性费用
        fee = notional * commission_rate + (notional * stamp_tax if side == -1 else 0.0)
        # 2) 滑点 + 冲击（按设定 bps 计）
        slip = notional * slippage_bps / 1e4
        # 3) 时机/延迟：成交价与决策价之差中，未被滑点解释的部分
        timing = side * (px - pdec) * t["shares"] - slip
        rows.append(dict(symbol=sym, date=d, side=t["side"], notional=notional,
                         fee=fee, slippage=slip, timing=timing,
                         total_bps=1e4 * (fee + slip + timing) / notional))
    return pd.DataFrame(rows)

attr = attribute(trades, mid)
total_notional = attr["notional"].sum()
print("总成交额 %.0f 元" % total_notional)
for col, name in [("fee", "佣金+税"), ("slippage", "滑点+冲击"), ("timing", "时机/延迟")]:
    print("%-10s 成本 %10.0f 元  占比 %5.2f%%  平均 %5.1f bps"
          % (name, attr[col].sum(), 100 * attr[col].sum() / total_notional,
             1e4 * attr[col].sum() / total_notional))

# 按方向聚合，找出"贵"的一侧
print(attr.groupby("side")["total_bps"].agg(["mean", "median", "count"]))
print(perf_report(res.equity))
```

## 常见坑

- **用收盘价做基准**：这是最普遍的错误，会把全部时机成本隐藏起来。
- **只看总成本不看分布**：平均滑点 20 bps 可能掩盖了 5% 的订单滑点超过 200 bps。必须看分位数。
- **归因到"市场"就停止**："这个月市场波动大"不是结论。要拆到"波动大 → 哪类订单变贵 → 下次怎么改"。
- **忽略未成交单**：只统计成交单会系统性低估成本（未成交的好机会也是成本）。
- **用模拟盘归因**：模拟盘的成交假设通常过于乐观，必须等实盘数据积累 1 个月以上。
- **忘记税与红利税**：持股期短的股息税对高分红策略是显著成本。
