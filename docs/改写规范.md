# 课程改写规范（零基础可读版）

> 本文件是全书 66 篇课程改写的统一标准。所有改写（含后续章节）都按此执行。
> 已完成的样板：[01-01 量化投资全景图](../01-入门/01-01-量化投资全景图.md)、
> [01-02 有效市场与alpha从哪来](../01-入门/01-02-有效市场与alpha从哪来.md)。

## 一、核心目标

**让完全没有基础的人也能看懂「到底在讲啥」，同时不牺牲专业正确性。**

读者读完一篇，应该能用大白话向别人复述这一课在讲什么，
并且**知道行业里那些词的正经叫法**，不会显得外行。

## 二、六条硬标准

### 1. 经典故事开场（每篇一个）
- 用一个真实、可核实的经典故事或人物引出主题，而不是直接抛定义
- 事实（人名、年份、数字、书名）必须核实，不许编造；不确定的宁可不用
- 故事讲完要**提炼出 1-3 条与本篇主题对应的要点**，不能只讲故事
- 找不到合适故事时，用一个具体、有画面感的生活场景替代，并说明它是虚构的例子

### 2. 术语 + 常识交代
- **专业术语一律保留正名**，不许用大白话替代（例如：不能把 beta 写成「市场给的」就算完）
- 每个术语第一次出现时：先给一句大白话解释，再给正名和行业用法
- 补上"圈内人都知道、但教材默认你会"的常识，例如：
  `IC 读作信息系数`、`我要赚 alpha 不是赚 beta`、`市场中性`、
  `统计显著 ≠ 经济显著`、`因子溢价`、`拥挤度`
- 目的是让读者以后跟人交流不露怯

### 3. 重要知识点单独讲透
- 核心概念**不许一笔带过**，要单独开小节，配：直觉 → 定义 → 例子 → 边界/误区
- 不怕篇幅长。宁可一篇 4000 字讲透一个点，不要 8 个点各写 200 字
- 每个关键点回答三问：**是什么 / 为什么重要 / 什么时候会失效**

### 4. 经典引述（每篇 1-3 处）
- 引述必须**紧扣当前论点**，不能硬塞名言装饰
- 每处引述后面用一两句话说明「这句话在这里是什么意思」
- 可用：费曼、格雷厄姆、塔勒布、博克斯、马尔基尔、索普、行业谚语等
- 引述内容要准确，注明出处（人 + 场合/书名）

### 5. 公式处理（分两级，用户已确认）
- **入门篇（01-入门 及 00-*）**：打 `零基础` 标签，**严格零公式**，纯文字 + 表格 + 比喻
- **其余章节**：核心公式保留，但必须"逐个讲透"：
  1. 公式出现前：先用白话讲清它想表达什么、为什么需要它
  2. 公式之后：**逐个符号**解释，并给一个能代入的具体小数字例子
  3. 补一句「这个公式什么时候不成立 / 有什么坑」
- 删掉那些只为炫技、不承担教学功能的公式堆砌

### 6. 代码与真实数字
- 保留可运行代码块（测试会逐个真实执行）
- 尽量**实跑代码**，把真实输出结果写进课文，用数字说话（像 01-01 / 01-02 那样）
- 明确交代：课程里的 `generate_demo_market` 是**合成数据**，用来学方法，
  不能用来判断真实收益（详见 [00-开始之前](../01-入门/00-开始之前.md)）
- 存成 `.py` 文件运行，不鼓励直接粘贴到终端

## 三、固定结构（元信息用 HTML 注释块）

```
<!--
id / title / category / level / order / prereq / tags / api
tags 里含「零基础」仅用于入门零公式篇
-->

# 标题

## 学完这一篇，你能做到      （3-4 条，可检验）
## 本篇要点                  （3-4 条）

---

## 一、从……说起             ← 经典故事，提炼要点
## 二、……到底是什么          ← 核心概念，术语+常识
## 三、……（重要知识点单独讲透）
## 四、……（用平台亲眼看看）   ← 代码 + 真实数字
## 五、……（边界 / 误区 / 坑）
## 六、把这一篇串起来        ← 回扣开头故事 + 经典引述

## 动手练习                  （2-3 条，强调「先猜再跑」）
## 延伸阅读
```

章节数量可增删，但「故事开场 → 概念 → 讲透 → 实证 → 误区 → 回扣」的节奏不变。

## 四、验证清单（每批必做）

1. `pytest tests/test_docs.py -q` —— 代码块真实执行、链接、字段、公式规则
2. `pytest tests/ -q` —— 完整套件
3. 解析校验：字数、公式数、代码块数、目标/要点/练习齐全
4. 内部链接目标存在
5. 代码块实跑，课文中引用的数字与实跑结果一致
6. git 提交并推送
