# 开始之前：把环境跑起来

## 学完这一篇，你能做到

- 在自己的电脑上把项目跑起来，并且知道每一步在做什么
- 说清楚 `qd` 是什么、为什么装完才有这个命令
- 跑通全部测试，确认你的环境和作者的一致
- 遇到常见报错能自己解决，而不是卡住

## 本篇要点

- 平台不是网站或 App，是你本地的一个代码库
- 装环境的核心就一句：`pip install -e .`，少了它就没有 `qd`
- 判断装好没有，只看一条：`qd demo` 有没有跑完
- 报错不可怕，先看最后 5 行再说

> **这一篇是全书的总入口。** 任何一篇的代码，都假设你已经按这里装好了环境。
> 如果你只是想先理解概念、暂时不碰代码，也可以跳过这里直接读
> [01-01 量化投资全景图](01-01-量化投资全景图.md)。

## 这本书不是纸上的，它是活的

你读的不是一本 PDF。它背后有一个**能真正运行的代码库**，名字叫 **Quant Dojo（量化道场）**，包含两部分：

| 部分 | 是什么 | 你要不要碰 |
| --- | --- | --- |
| **66 篇课程**（就是你在读的） | Markdown 文件，每篇带可运行的代码 | 要读 |
| **一个 Python 引擎**（代码包叫 `qd`） | 数据、因子、回测、绩效、组合优化等真实实现 | 要跑，但不必读源码 |

**后面凡是出现"平台"，指的就是这个代码库**——不是网站、不是 App、不用注册账号。它在你的电脑里。

## `qd` 是什么

`qd` 是**这个引擎的命令行入口**，读作 "Q D"。

你安装这个项目之后，系统会多出一个叫 `qd` 的命令。就像 `git`、`docker` 一样，它是一段**程序的快捷方式**——你在终端里敲 `qd backtest`，系统就去找这个程序，让它替你跑一次回测。

为什么要有它？因为引擎的功能写在一堆 Python 文件里，直接调用很麻烦。`qd` 把这些功能包成了十几个简单的命令：

| 命令 | 干什么 | 什么时候用 |
| --- | --- | --- |
| `qd demo` | 一键跑完全流程自检 | **装好环境后第一件事**，验证一切正常 |
| `qd lessons` | 列出全部课程 | 想看看有哪些课 |
| `qd lesson 05-05` | 在终端里读一篇课 | 学习时 |
| `qd search 夏普` | 搜索课程 | 忘了在哪篇讲过 |
| `qd factors` | 列出全部 49 个因子 | 查因子 |
| `qd factor mom_12_1` | 单个因子的完整研究报告 | 研究因子 |
| `qd backtest dual_momentum` | 跑一个策略的回测 | 检验策略 |
| `qd grid dual_momentum` | 参数网格搜索 | 调参（会警告过拟合） |
| `qd wf dual_momentum` | 滚动前推验证 | 样本外检验 |
| `qd overfit dual_momentum` | 白噪声过拟合实验 | 理解过拟合 |
| `qd serve` | 启动网页界面 | 想看图、点按钮 |

> **新手只需要记住两个：`qd demo` 和 `qd serve`。**
> 前者验证环境有没有装好，后者打开网页版。

## 搭建环境（只需做一次）

这是本篇唯一需要你照着敲的流程。我把它写成"复制 → 粘贴 → 回车"的形式，你不需要理解每一行。

**前提**：你需要有 Python（3.10 以上）。怎么装 Python 不在本书范围，网上教程很多，装完在终端验证一下：

```bash
python3 --version
```

只要打印出 `3.10` 或更高就行。

**第 1 步：拿到代码**

```bash
git clone https://github.com/dejunyu/quant-dojo.git
cd quant-dojo
```

（没有 `git`？也可以去 GitHub 页面点 "Download ZIP"，解压后 `cd` 进那个目录。）

**第 2 步：创建虚拟环境**

```bash
python3 -m venv .venv
```

> **什么是"虚拟环境"？** 简单说，它是一个**只属于这个项目的 Python 小隔间**。你的电脑上可能还有别的 Python 项目，各自的依赖版本会打架。虚拟环境让这个项目独占一套依赖，互不干扰。这是 Python 的标准做法，不是本书发明的。

**第 3 步：激活它**

```bash
source .venv/bin/activate        # macOS / Linux
```

Windows 用户用这条：

```bash
.venv\Scripts\activate
```

激活成功后，你的命令行提示符前面会多出 `(.venv)` 几个字——**这很重要，说明你现在在这个隔间里**。如果没看到，说明没激活成功。

**第 4 步：安装依赖和项目本身**

```bash
pip install -r requirements.txt
pip install -e .
```

这两行在干什么：

- 第一行装第三方库（numpy、pandas 这些，本书不重复造轮子）
- 第二行 **`-e .` 把项目本身装进环境**，末尾那个点表示"当前目录"。**不装这一行，就没有 `qd` 这个命令**

**第 5 步：验证**

```bash
qd demo
```

如果看到一堆策略分析和绩效数字滚过去，最后没有报错，**说明环境装好了**。可以开始学习了。

## 怎么运行书里的代码

**你只需要现在学会这一次，以后直接照做即可**，我不会再重复。

**把代码存成文件再运行，不要直接粘贴到终端。** 因为粘贴多行代码时，终端经常把缩进吃错，报一堆你看不懂的错。

```bash
# 1) 确保在项目目录里
cd ~/quant-dojo

# 2) 每次打开新终端都要先激活（提示符出现 (.venv) 才算成功）
source .venv/bin/activate

# 3) 存好文件后运行
python my_first_strategy.py
```

## 怎么跑测试

这个项目自带一套自动化测试。**它们不是摆设，而是这本书的可信度来源**——测试会检查两件事：

1. 引擎算得对不对（回测有没有偷看未来、因子有没有算错）
2. **课文里的每一段代码能不能真的跑通**

跑全部测试：

```bash
pytest tests/ -v
```

大约需要 7 分钟，最后应该看到 `132 passed, 1 skipped`。如果你看到的是这个数字，说明你的环境和作者的环境是一致的。

只跑某一类：

```bash
pytest tests/test_docs.py -v          # 只检查课文代码和链接（最慢）
pytest tests/test_no_lookahead.py -v  # 只验证"回测没偷看未来"
```

> **建议你至少跑一次 `test_no_lookahead.py`。**
> 它做的事情很极端：把所有"未来数据"随机打乱，然后断言切点之前的净值曲线**必须完全不变**。如果策略偷看了未来，这条线一定会变。这是我在本书里最喜欢的一个测试——**它用代码证明了"没作弊"，而不是嘴上说说。**

## 遇到问题怎么办

新手最容易卡在这几个地方，我把解决办法列出来：

| 报错信息 | 原因 | 怎么解决 |
| --- | --- | --- |
| `command not found: qd` | 没做第 4 步的 `pip install -e .` | 回到项目目录，激活环境后重跑 `pip install -e .` |
| `No module named qd` | 同上，或者没激活虚拟环境 | 先 `source .venv/bin/activate`，确认提示符有 `(.venv)`，再装一次 |
| `No module named numpy` | 第 4 步的 `pip install -r requirements.txt` 没跑 | 补跑一次 |
| `command not found: python` | 系统只有 `python3` | 把命令里的 `python` 换成 `python3` |
| 提示符前面没有 `(.venv)` | 虚拟环境没激活 | 重新执行 `source .venv/bin/activate` |
| `Permission denied` | 用了系统 Python 或没权限 | 确认在项目目录、且激活了 `.venv`；不要用 `sudo` |
| `pip` 很慢或超时 | 网络问题 | 换国内镜像：`pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple` |
| 测试跑出来是 `127 passed` 而非 `132` | 你的 Python 版本较老，跳过了部分测试 | 一般无妨；升级到 3.11+ 可完全一致 |

> **还有问题怎么办？** 把报错的**最后 5 行**复制下来，去仓库的 Issues 页面搜一下——报错信息越长越专业，越可能有人遇到过。这本身也是量化研究者的基本功：**遇到问题先看报错，而不是先怀疑自己。**

## 用代码验证环境

除了 `qd demo`，你也可以用下面这段直接检查：**它不依赖任何命令行参数，跑通就说明引擎和数据都正常。**

```python
# 环境自检：能跑完这段，说明安装成功
import qd
from qd.data.synthetic import generate_demo_market
from qd.factors import list_factors

md = generate_demo_market(n_symbols=10, seed=1)
print("qd 版本:", qd.__version__)
print("行情:", len(md.symbols), "只股票 ×", len(md.dates), "个交易日")
print("内置因子:", len(list_factors()), "个")
print("自检通过")
```

如果这段能打印出"自检通过"，说明 Python 环境、依赖、以及项目本身都装好了。

## 动手练习

- 跑一次 `qd demo`，把最后输出的那几行贴到自己的笔记里——以后环境出问题时，这就是你的"正常状态"基线。
- 故意制造一个错误：在项目目录外打开新终端（不激活虚拟环境）敲 `qd demo`，看看报什么错。**认得出这个错，你以后就不会被它卡住。**
- 跑一次 `pytest tests/test_no_lookahead.py -v`，找到那个"打乱未来数据后净值不变"的断言，读一遍它的注释。
