# 多因子选股

## 学完这一篇，你能做到

- 说清"从因子到组合"中间隔着的完整流程
- 理解选股域、打分、权重、约束四步各自在解决什么
- 知道为什么"指数增强"是新手最该先做的方向
- 用平台跑一次多因子组合，并对比集中度与调仓频率的影响

## 本篇要点

- 全流程：**选股域 → 打分 → 权重 → 约束**
- 集中度（top_k）是"暴露强度 vs 分散度"的旋钮
- 调仓频率直接决定换手与成本（03-04）
- 指增有**明确基准和明确考核**，最不容易自欺

## 一、从"把论文变成产品"说起

1990 年，一个还在读博的 24 岁年轻人 **克里夫·阿斯尼斯**（Cliff Asness）进了高盛资产管理部，组建了一个量化研究小组。

1995 年，他说服高盛合伙人拿出 **1000 万美元**试水；策略跑通、规模滚到约 1 亿美元后，对外成立了 **Global Alpha**。**1997 年他离开高盛**，**1998 年与 David Kabiller、Robert Krail、John Liew 一起创立了 AQR**（在纽约，连同 10 名员工，第一个产品是一只对冲基金）。（[AQR 官网 Our Firm](https://www.aqr.com/Our-Firm/About-Us)）

> **AQR 的全称是 Applied Quantitative Research——"应用"量化研究。**
> 这个"应用"二字，正是本篇的主题：
> **从"因子在论文里显著"，到"因子能变成一笔可交易的钱"，中间隔着一整层工程。**
>
> 05 章的七道工序（构造、清洗、中性化、IC、分层、衰减、正交、合成）
> 解决的是"**这个因子有没有信息**"；
> 这一篇解决的是"**怎么把这点信息，变成一个买了不会崩的组合**"。

> 顺带说个真实的对照：AQR 的资产管理规模在 **2007 年约 390 亿美元，2008 年跌到约 170 亿**，2010 年又回到 330 亿左右。
> **同一个因子体系，净值曲线可以难看成这样。**
> 这不是能力问题，是 2008 年那种年份，所有"看起来低相关的策略"会一起失灵（04-02 讲过危机中相关性上升）。

## 二、完整流程（四步，逐个讲透）

```text
选股域 → 打分 → 权重 → 约束
（谁能买）（买谁）（买多少）（必须满足什么）
```

| 步骤 | 干什么 | 最容易错在哪 |
| --- | --- | --- |
| **1. 选股域** | 决定"哪些股票有资格被选" | 用了当前成分/当前市股（02-05 幸存者） |
| **2. 打分** | 多因子合成一个综合分（05-09） | 因子相关太高，等于重复下注（05-08） |
| **3. 权重** | 从分数到持仓 | 集中度失控 |
| **4. 约束** | 行业/市值/换手限制 | 约束太松变成"风格押注" |

### 第 1 步：选股域（最容易被低估）

**选股域** = 你的可选池。听起来只是个筛子，但它决定了**你根本没机会买到什么**。

| 常见筛选 | 为什么 |
| --- | --- |
| 剔除 ST、退市整理 | 风险与流动性（03-01） |
| 剔除上市不足 N 日 | 新股波动极大 |
| 流动性下限（成交额） | 买不进就没意义（03-05） |
| **必须含已退市股票** | 否则就是幸存者偏差（02-05） |

> ⚠️ **最后一条尤其关键**：如果你的选股域只包含"今天还在市"的股票，
> 那么你的回测**天生就剔除了所有失败者**——这是 02-05 讲的最标准形态。
> **而且它不会报错，只会让曲线更好看。**

### 第 2、3 步：从打分到权重

| 权重方式 | 怎么做 | 特点 |
| --- | --- | --- |
| **等权** | 选中的每只 1/k | 最稳、最抗过拟合 |
| **分数加权** | 按综合分线性分配 | 偏向强信号 |
| **市值加权** | 按市值分配 | 接近指数 |
| **最优化** | 解均值方差 | 对估计误差极敏感（05-09 讲过为什么常输给等权） |

> **`top_k` 这个参数，本质是在调"集中度"。**
> `top_k=10` 意味着极度集中：单票 10%，任何一只暴跌都重创组合。
> `top_k=50` 意味着一篮子：暴露被稀释，但单票风险小。
>
> **这是"信号强度 vs 分散度"的直接权衡，没有标准答案，取决于你能承受多大回撤。**

### 第 4 步：约束

| 约束 | 防的是什么 |
| --- | --- |
| 行业偏离上限 | 变成"押注行业"（05-04） |
| 市值暴露中性 | 变成"押注小盘"（01-05 的教训） |
| 换手上限 | 成本失控（03-04） |
| 单票权重上限 | 黑天鹅（04-02） |

## 三、为什么**指增**是最好的入门方向

01-04 提过一句，这里讲透。

**指数增强** = 以指数为基准，在允许的偏离范围内尽量多赚。

| 好处 | 为什么 |
| --- | --- |
| **有明确基准** | 超额收益一目了然，没法浑水摸鱼 |
| **有明确考核** | 信息比率 IR、跟踪误差 TE（01-05 讲过） |
| **不容易自欺** | "大盘涨所以我也涨"这种话，在指增里说不出口 |

而"超额"到底怎么衡量？行业里用**信息比率**（IR）：

$$ \mathrm{IR} = \frac{\mathbb{E}[r_p - r_b]}{\sigma(r_p - r_b)} $$

| 符号 | 白话 |
| --- | --- |
| $r_p$ | 你的组合收益 |
| $r_b$ | 基准（比如沪深 300）收益 |
| 分子 | **超额收益**：比基准多赚多少 |
| 分母 $\sigma(r_p-r_b)$ | **跟踪误差 TE**：你偏离基准有多剧烈 |

> **注意分母不是"总波动"，而是"偏离基准的波动"。**
> 一个满仓小盘股的组合可能总波动很大，但如果它和基准偏离得也很剧烈，
> **IR 反而会很低**——因为它的"超额"主要来自风格漂移，不稳定。
>
> 一句话：**夏普问"你值不值"，IR 问"你和基准比，稳不稳地多赚"。**
> 指增产品的考核几乎只看 IR（01-05 讲过这两个指标的差别）。

> 相比之下，一个"绝对收益"策略最难的地方是：**你永远不知道赚的是本事还是运气**。
> 而指增把参照物钉死在基准上——**超额是正是负，一目了然。**

## 四、用平台跑一次多因子组合

按 [00-开始之前](../01-入门/00-开始之前.md) 装好环境，把下面这段存成文件跑一次：

```python
import warnings
warnings.filterwarnings("ignore")
from qd.backtest import Backtest, BacktestConfig
from qd.strategy.builtin import factor_long_only
from qd.data.synthetic import generate_demo_market
from qd.metrics.perf import perf_report

md = generate_demo_market(n_symbols=50, start="2018-01-01", end="2024-12-31", seed=7)
cfg = BacktestConfig(initial_cash=1_000_000, commission_rate=0.0003, slippage_bp=5.0)
FACTORS = ["mom_12_1", "bp", "roe_q"]

# 1) 基准组合：三因子、持 10 只、月度调仓
res = Backtest(md, factor_long_only(factors=FACTORS, top_k=10, rebalance=20), cfg).run()
rep = perf_report(res.equity, rf=0.02)
print(f"top_k=10: 年化={rep['annual_return']:.3f} Sharpe={rep['sharpe']:.2f} "
      f"回撤={rep['max_drawdown']:.3f} 交易={len(res.trades)}")

# 2) 集中度对比
for k in (5, 10, 20, 30):
    r = Backtest(md, factor_long_only(factors=FACTORS, top_k=k), cfg).run()
    print(f"top_k={k}: Sharpe={perf_report(r.equity, rf=0.02)['sharpe']:.2f}")

# 3) 调仓频率：注意它属于 BacktestConfig，不是策略参数
for reb in ("daily", "weekly", "monthly"):
    c = BacktestConfig(initial_cash=1_000_000, commission_rate=0.0003,
                       slippage_bp=5.0, rebalance=reb)
    r = Backtest(md, factor_long_only(factors=FACTORS, top_k=10), c).run()
    print(f"调仓={reb:8s}: Sharpe={perf_report(r.equity, rf=0.02)['sharpe']:+.2f} "
          f"交易={len(r.trades)}")
```

我实跑的结果：

```
top_k=10: 年化=-0.476 Sharpe=-3.89 回撤=-0.991 交易=6956

top_k=5:   Sharpe=-3.72
top_k=10:  Sharpe=-3.89
top_k=20:  Sharpe=-2.32
top_k=30:  Sharpe=-1.31

调仓=daily  : Sharpe=-3.89 交易=6956
调仓=weekly : Sharpe=-0.90 交易=2185
调仓=monthly: Sharpe=-0.03 交易=606
```

**这里有两个读点，第二个是"反常"：**

**第一，集中度确实有影响**：`top_k` 从 5 到 30，夏普从 -3.72 一路改善到 -1.31。**分散得越开，亏得越少**——因为单票的极端波动被摊薄了。

**第二，调仓频率的影响是决定性的**（这是本篇最该记住的数字）：

| rebalance | 夏普 | 年化 | 成交笔数 |
| --- | --- | --- | --- |
| daily | **-3.89** | -47.6% | **6956** |
| weekly | -0.90 | -14.9% | 2185 |
| monthly | **-0.03** | -0.3% | **606** |

> **从"每天调仓"改成"每月调仓"，成交从 6956 笔降到 606 笔，夏普从 -3.89 变成 -0.03。**
> 策略逻辑一个字没改，因子也没换，**只是少动了手脚**。
>
> 这就是 01-01 里那个双均线故事的完整版：
> **"不是策略不赚钱，是赚的钱全交了手续费"**（03-04 的成本、05-07 的净 IC，说的都是这件事）。

> ⚠️ **一个踩过的坑，值得专门写下来**：
> `factor_long_only(...)` 的签名里**也有一个 `rebalance` 参数**，但它并不生效——
> **调仓频率真正由 `BacktestConfig(rebalance=...)` 控制**。
> 我第一次调用时把 `rebalance=20` 传给了策略，结果四档参数跑出来**一模一样**（都是 -3.56）。
>
> **这就是"参数放错位置"的典型症状：扫描出来一排完全相同的数字。**
> 而当它发生时，人最容易得出的错误结论是——"**市场对这个参数不敏感**"。
> **正确的第一反应永远是：这个参数，真的生效了吗？**
> （07-02 那个 `n_std` 完全不生效的 bug，是同一个症状的另一种原因。）

> ⚠️ **另一个必须说明的点**：这个策略年化 **-45.5%**、回撤 **-98.8%**，是灾难性的。
> 但这不说明"多因子选股不行"——它说明**在只埋了弱信号的合成数据上，任何重仓选股策略都会被噪声吃掉**。
> 记住 00-01 那句：**合成数据用来学方法，不能用来判断策略好坏。**

## 五、归因：先问"我赚的是什么钱"

01-05 讲过收益分解，这里落地：

| 你以为是 | 实际可能是 | 怎么查 |
| --- | --- | --- |
| 选股能力（alpha） | 押对了小盘/价值风格 | 中性化后重跑（05-04） |
| 因子有效 | 恰好赶上了某段行情 | 分年看、滚动前推（06-06） |
| 组合分散 | 五只股票其实是同一个行业 | 看相关性与行业暴露 |

> **最有力的一招，永远是"中性化之后再看一次"。**
> 如果中性化后收益大幅下降，说明原来的收益**大部分来自你不想要、也没意识到的暴露**（05-04 的实跑数字就是这么用的）。

## 六、把这一篇串起来

回到 AQR 那个"应用"二字。

05 章教你**怎么判断一个因子有没有信息**；这一篇教你**怎么把这点信息变成一个能下单的组合**。两者的差距，就是"研究"和"产品"的差距。

> 而这一步最容易失手的地方，不是模型不够聪明，是**四个枯燥的环节**：
> 选股域有没有含退市股、因子之间是不是重复、集中度敢不敢放开、约束有没有真的生效。
> **这四件事，每一件都能让一个"IC 0.03 的好因子"变成一条亏钱的曲线。**

> 一句话收尾：
> **因子研究回答"有没有用"，组合构建回答"能不能用"。**
> 而绝大多数"看起来有效"的因子，死在了第二个问题里——
> **不是因为它不真，是因为它装不进一个能活下来的组合。**
