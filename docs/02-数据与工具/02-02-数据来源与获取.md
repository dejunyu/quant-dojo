# 数据来源与获取

## 学完这一篇，你能做到

- 选数据源时不再只问"有没有这个字段"，而是问三个更该问的问题
- 说清免费源和付费源真正的差别（**不是准不准**）
- 理解"换数据源不动策略"这个设计为什么值钱
- 知道 A 股、美股、加密货币各自最容易踩的数据坑

## 本篇要点

- 选源看三维：覆盖与历史长度、口径一致与可追溯、合规
- 免费源够学习用；**生产环境买的是稳定性、可追溯性和服务支持**
- 平台把所有来源统一成 `MarketData`，换源只改一行，策略不动
- 交易日历一定要用平台的 `trading_days`，别自己拿工作日近似

---

## 一、从"数据本来是奢侈品"说起

回到 02-01 那台彭博终端：1980 年代，想要一份干净、对齐、能即时比较的行情，**得付每年两万多美元租一台专用机器**。数据是少数机构的特权。

今天情况反过来了。国内出现了一批**开源免费**的金融数据接口——`akshare`、`Tushare`、`baostock` 等，把 A 股行情、财务、指数、宏观数据封装成几行 Python 就能调用的函数。一个学生坐在宿舍里，免费就能拉到十几年的日线数据，这在三十年前不可想象。

但故事还有另一半：

> **免费源几乎都是"社区维护"的。** 它们很多靠解析公开网页或第三方接口取数，
> **上游页面一改版，接口就失效**；字段定义也可能悄悄变，且不保留历史快照。
> 所以机构里至今仍在用 Wind、聚源、Bloomberg 这些付费源——
> **不是因为免费数据算错了，而是因为生产环境不能容忍"今天早上突然拉不到数"。**

> 这个对比给出了本篇最实用的一句话：
> **免费源卖给你的是"数据"，付费源卖给你的是"确定性"。**
> 学习阶段前者完全够用；做实盘、进机构，几乎必然切到后者。

---

## 二、选源的三个维度（别只问"有没有"）

选数据源时，新手最常问"有没有这个字段"。更该问的是这三件：

| 维度 | 该问什么 | 为什么致命 |
| --- | --- | --- |
| **覆盖与历史长度** | 至少 10 年、跨两轮牛熊吗？早年数据质量如何？ | 因子检验样本太短，容易把噪声当规律（02-01 讲的有效观测数） |
| **口径一致与可追溯** | 同一字段会不会静默改定义？保留历史快照吗？ | 数据被悄悄改了，你分不清结果变化来自哪里（02-06） |
| **合规** | 许可允许商业使用吗？能再分发吗？ | 个人学习一般没问题，**用于公司产品前必须核实许可** |

> 第 2 条里的 **point-in-time（时点快照）** 是付费源最值钱的地方：
> 能查到"在 2020 年 6 月那天，市场看到的这份财报长什么样"，包括后来被更正前的旧版本。
> **没有它，你就无法做严格的历史回测**（02-04）。

## 三、主流数据源对比

| 来源 | 类型 | 覆盖 | 优点 | 局限 |
| --- | --- | --- | --- | --- |
| **akshare** | 免费开源 | A 股/期货/宏观/基金，覆盖极广 | 免费、接口多、社区活跃 | 依赖网页抓取，易随改版失效；**不宜作生产依赖** |
| **Tushare Pro** | 免费+积分 | A 股行情、财务、指数、宏观 | 结构化好、文档清晰 | 免费额度受积分限制，高频调用需付费 |
| **baostock** | 免费 | A 股日线/分钟、财务、复权因子 | **提供复权因子**，适合研究 | 更新频率与覆盖不如商业源 |
| 聚宽（JoinQuant） | 平台 | A 股、因子库、在线回测 | 研究与回测一体化 | 数据与策略绑定平台，导出受限 |
| Wind（万得） | 付费 | 全资产、深度财务与另类数据 | 口径权威，机构标准 | 费用高、终端授权受限 |
| 聚源 | 付费 | A 股深度财务与事件 | 财务数据质量高 | 费用高 |
| Bloomberg | 付费 | 全球资产 | 全球覆盖、历史长 | 极其昂贵 |
| **交易所 / 官方** | 免费 | 交易规则、指数成分、公告 | **权威、无许可问题** | 非结构化，需自行解析 |

> **结论很直接**：学习阶段 `akshare + baostock` 完全够用；实盘或入职后切付费源。
> 另外别小看最后一行——**交易所官网是唯一没有许可争议、也最权威的来源**，
> 交易规则、指数成分调整、公告都该以它为准。

## 四、三个市场，三套坑

### A 股

- **日线行情**：akshare / Tushare / baostock 均可，注意**复权口径与停牌处理**（02-03）。
- **财务数据**：要区分合并报表与母公司报表，且**必须拿披露日**（02-01、02-04）。
- **指数成分与权重**：从中证指数公司或交易所公告取，注意成分调整是**定期生效**、**提前公告**——公告日 ≠ 生效日，别混。
- **交易日历**：用平台的 `trading_days`，别自己用"周一到周五"近似——**节假日和调休会让你错得一塌糊涂**。

> 补个常识：**调休**会让某个周六变成交易日、某个周一变成休市日。
> 自己写 `pd.bdate_range()` 会把这些日子算错，进而让整张面板错位一格——
> 这又是一个"不报错但全错"的坑。

### 美股

- 免费：交易所/券商 API、部分开源库提供的 Yahoo Finance 接口（注意条款与稳定性）。
- 付费/学术：Polygon、Tiingo、Nasdaq Data Link（原 Quandl）、CRSP / Compustat。
- 特点：**拆股与分红调整**必须处理（类似 A 股复权）；低价股、场外股很多，样本常要过滤（如价格 > 5 美元）。

> **CRSP / Compustat** 是学术圈最常用的两套数据库，01-05 讲 Fama-French 三因子、
> 02-05 讲幸存者偏差时都绕不开它们——**CRSP 的价值之一正是"包含退市股票"**，
> 而这一点恰恰是免费源最常缺的。

### 加密货币

- 直接对接交易所 API（REST / WebSocket），历史 K 线通常免费且质量不错。
- 特点：**24/7 无休、无涨跌停、没有统一收盘时间**；不同交易所价格有差异，要选主流量价源。
- 坑：交易所宕机期间的缺失、永续合约与现货价格不同、合约换月跳变。详见 [03-03 加密货币市场](../03-市场与交易规则/03-03-加密货币市场.md)。

## 五、"换源不动策略"为什么值钱（单独讲透）

平台把所有来源统一成一个 `MarketData` 对象。**策略代码只依赖这个对象，不依赖具体来源。**

```python
from qd.data import MarketData
from qd.data.synthetic import generate_demo_market
from qd.data.akshare_feed import AkshareFeed
from qd.utils.calendar import trading_days

# 路径 A：合成数据（离线、可复现，适合教学与单元测试）
md_syn = generate_demo_market(n_symbols=50, start="2018-01-01", end="2024-12-31", seed=7)

# 路径 B：真实 A 股（需联网）
md_a = AkshareFeed().load(["600519", "000300", "601318"], "2020-01-01", "2024-12-31")

# 两条路径的对象接口完全一致，策略代码可以原样复用
def sanity_check(md):
    close = md.close()
    return {
        "n_days": len(md.dates),
        "n_symbols": len(md.symbols),
        "missing": round(close.isna().mean().mean(), 4),
        "max_abs_ret": round(md.returns().abs().max().max(), 4),
    }

print(sanity_check(md_syn))
print(sanity_check(md_a))

# 从已有的 DataFrame 直接组装（例如你自己的 parquet 缓存）
md_custom = MarketData.from_dataframes({
    "open": md_a.open(), "high": md_a.close(), "low": md_a.close(),
    "close": md_a.close(), "volume": md_a.volume(),
})

# 交易日历：不要用 pandas 的工作日假设
cal = trading_days("2024-01-01", "2024-12-31", market="A")
print(len(cal), cal[:3])
```

> ⚠️ **运行提示**：`AkshareFeed()` 需要联网且要装 `akshare`（见 [00-开始之前](../01-入门/00-开始之前.md)）。
> 没网或只想跑通流程时，把路径 B 那几行注释掉即可——**路径 A 完全离线**。
> 教材测试会自动跳过需要联网的代码块，所以这段不会让 CI 变红。

**这个设计为什么重要？** 因为它把"数据从哪来"和"策略怎么算"彻底分开了：

| 没有这层解耦 | 有这层解耦 |
| --- | --- |
| 换数据源要把所有策略代码翻一遍 | **只改获取数据的那一行** |
| 合成数据和真实数据要写两套策略 | 同一份策略，两个都能跑 |
| 想验证"结果差异是数据还是逻辑"很难 | 固定代码、换数据，差异一目了然 |

> 这正是 02-06 讲的"可复现三件套"。用那一篇的式子说，一次回测的结果可以写成：
>
> $$V = \mathrm{Backtest}(D,\ C,\ \theta)$$
>
> 逐个拆开：$V$ 是净值序列（结果），$D$ 是**数据版本**，$C$ 是**代码版本**，$\theta$ 是参数。
> 而这层解耦的价值恰恰在于：**换数据源只动 $D$，$C$ 和 $\theta$ 原封不动**。
> 于是"结果变了"一定来自数据，定位问题只需一秒。
> 好的工程结构，本身就是一种**归因工具**。

## 六、工程化建议

1. **接口与策略解耦**：策略只吃 `MarketData`，取数逻辑集中在一个模块。
2. **落盘再研究**：拉到的数据先存成带版本的 Parquet（02-06），别每次研究都重新联网拉。
3. **保留原始响应**：原始数据只读、永不覆盖；清洗产出到独立目录。
4. **监控变更**：每次拉取记录行数、缺失率、异常值数量，突变要告警。
5. **合规留痕**：记录来源与许可条款，尤其是将来可能商业化的项目。

## 七、把这一篇串起来

回到 1982 年那台终端和今天的 `akshare`。

中间隔了四十年，不变的其实只有一件事：**数据必须能被干净地拿到、稳定地对上、出问题时能追溯**。变的只是价格——从每年两万多美元，变成 `pip install` 一行命令。

> 但"便宜"也带来一个新风险：**太容易拿到，就容易跳过检查。**
> 三十年前你花大价钱买数据，会逐字段核对；
> 今天三行代码拉下来就开跑，于是**口径、时点、幸存者**这三个坑全被略过——
> 而它们恰好就是 02-03、02-04、02-05 三篇要补的课。

> 一句话收尾：
> **数据源不是"去哪儿下载"，是"我凭什么相信这份数"。**
> 能把这句话答清楚，你才真的开始做量化研究了。
