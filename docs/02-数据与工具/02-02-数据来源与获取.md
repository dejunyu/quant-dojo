# 数据来源与获取

## 一、选择的三个维度

选数据源时不要只问"有没有这个字段"，要问三件事：

1. **覆盖与历史长度**：因子检验至少需要 10 年以上、跨越两轮牛熊的样本；A 股很多免费源的历史数据从 2005 年或更晚开始，且早年的复权质量较差。
2. **口径一致性与可追溯**：同一字段在不同时间是否会静默变更定义？数据商是否会保留历史快照（point-in-time）？这是付费源最值钱的地方。
3. **合规**：多数免费数据源的使用条款禁止商业再分发或未经授权的商业使用。个人学习一般没问题，用于公司产品前必须核实许可（视数据商具体许可条款而定）。

## 二、主流数据源对比

| 来源 | 类型 | 覆盖 | 优点 | 局限 |
| --- | --- | --- | --- | --- |
| akshare | 免费开源 | A 股/期货/宏观/基金，覆盖面极广 | 免费、接口多、社区活跃 | 接口依赖网页抓取，易随页面改版失效；不适合作生产依赖 |
| Tushare Pro | 免费+积分 | A 股行情、财务、指数、宏观 | 结构化程度好，文档清晰 | 免费额度受积分限制，高频调用需付费 |
| baostock | 免费 | A 股日线/分钟线、财务、复权因子 | 提供复权因子，适合研究 | 更新频率与覆盖不如商业源 |
| 聚宽（JoinQuant） | 平台 | A 股、因子库、在线回测 | 一体化研究与回测环境 | 数据与策略绑定平台，导出受限 |
| Wind（万得） | 付费 | 全资产、深度财务与另类数据 | 口径权威，机构标准 | 费用高，终端授权限制 |
| 聚源 | 付费 | A 股深度财务与事件 | 财务数据质量高 | 费用高 |
| Bloomberg | 付费 | 全球资产 | 全球覆盖、历史长 | 极其昂贵 |
| 交易所/官方 | 免费 | 交易规则、指数成分、公告 | 权威、无许可问题 | 非结构化，需自行解析 |

**结论很直接**：学习阶段用 akshare + baostock 完全够用；做实盘或入职机构后，几乎必然使用付费源——不是因为免费源数据不准，而是因为**生产环境需要稳定性、可追溯性与服务支持**。

## 三、按市场获取

### A 股

- **日线行情**：akshare、Tushare、baostock 均可；注意复权口径与停牌处理。
- **财务数据**：需要区分合并报表与母公司报表，且要拿披露日。
- **指数成分与权重**：从中证指数公司或交易所公告获取，注意成分调整是**定期生效**（通常为每年 6 月与 12 月的第二个星期五的下一交易日）而**提前公告**，两者不能混淆。
- **交易日历**：用平台的 `trading_days`，避免自己用工作日近似（节假日与调休会出错）。

### 美股

- 常用免费途径：交易所/券商 API、部分开源库提供的 Yahoo Finance 接口（注意其条款与稳定性）。
- 付费：Polygon、Tiingo、Nasdaq Data Link（原 Quandl）、CRSP/Compustat（学术）。
- 特点：**拆股与分红调整**必须处理（类似 A 股复权）；且存在大量场外与低价股，样本需要过滤（如价格 > $5、市值 > 一定门槛）。

### 加密货币

- 直接对接交易所 API（REST/WebSocket），历史 K 线通常免费且质量不错。
- 特点：**24/7 无休、无涨跌停、无统一收盘时间**；不同交易所之间价格存在差异，需要选择主流量价源。
- 数据陷阱：交易所宕机期间的缺失、永续合约与现货价格不同、合约换月导致的跳变。详见 [03-03-加密货币市场](../03-市场与交易规则/03-03-加密货币市场.md)。

## 四、平台数据层的正确用法

平台把所有来源统一为 `MarketData` 对象，策略代码只依赖这个对象，不依赖具体来源。这是刻意的解耦：**换数据源时只改一行，不动策略**。

```python
from qd.data import MarketData
from qd.data.synthetic import generate_demo_market
from qd.data.akshare_feed import AkshareFeed
from qd.utils.calendar import trading_days

# 路径 A：合成数据（离线、可复现，适合写单元测试与教学）
md_syn = generate_demo_market(n_symbols=50, start="2018-01-01", end="2024-12-31", seed=7)

# 路径 B：真实 A 股（需联网）
md_a = AkshareFeed().load(["600519", "000300", "601318"], "2020-01-01", "2024-12-31")

# 两条路径的对象接口完全一致，策略代码可以原样复用
def sanity_check(md):
    close = md.close()
    return {
        "n_days": len(md.dates),
        "n_symbols": len(md.symbols),
        "missing": round(close.isna().mean().mean(), 4),
        "max_abs_ret": round(md.returns().abs().max().max(), 4),
    }

print(sanity_check(md_syn))
print(sanity_check(md_a))

# 从已有的 DataFrame 直接组装（例如你自己的 parquet 缓存）
md_custom = MarketData.from_dataframes({
    "open": md_a.open(), "high": md_a.close(), "low": md_a.close(),
    "close": md_a.close(), "volume": md_a.volume(),
})

# 交易日历：不要用 pandas 的工作日假设
cal = trading_days("2024-01-01", "2024-12-31", market="A")
print(len(cal), cal[:3])
```

## 五、工程化建议

1. **永远做本地缓存**。网络源会失效、会限流。把拉到的数据立刻落盘为 parquet，并附带一个版本号（拉取时间 + 数据哈希）。
2. **记录快照而非覆盖**。基本面数据会被修正（财报重述），保留每次拉取的快照才能做 point-in-time 回测。
3. **失败要显式**。网络请求失败时不要静默返回空 DataFrame，否则你会把"数据缺失"误认为"停牌"。
4. **限制频率**。免费源对调用频率敏感，批量拉取时应加节流与重试退避。
5. **验证字段含义**。对任何新字段，先抽样与交易所公告或行情软件核对几个日期，确认口径一致再大规模使用。

## 常见坑

- **把网页抓取接口当生产依赖**。akshare 这类库依赖第三方页面结构，改版即失效，接口调用也可能突然变慢或返回空。生产环境要么用付费 API、要么自建缓存层。
- **忽略许可条款**。免费不等于可商用，把抓取的数据打包卖给他人可能违反服务条款（视数据商具体许可条款而定）。
- **混用两个数据源的同名字段**。比如 A 源的 `volume` 是手、B 源是股，直接拼接会产生 100 倍的误差，而且不会报错。
- **不保存数据版本**。半年后重跑回测得到不同结果，你无法判断是代码变了还是数据变了。

## 延伸阅读

- akshare 官方文档与数据源说明——学习阶段获取 A 股数据的主要参考，具体接口以官方最新文档为准。
- 中证指数公司公布的指数编制方案——指数成分与调整规则的权威依据。
- 交易所数据服务与行情接口说明（上交所、深交所官方发布）——字段定义与交易日历的权威来源。
